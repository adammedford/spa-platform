## What is asked of the integrator

Five edits in files AGENTS.md reserves to the integrator. Items 1 to 4 are wording and dead code
that ADR-0016 already decided; item 5 is the registration Q45 asked for.

1. **Remove the step `Plan policy (P-01 to P-03)`** from `.github/workflows/ci.yml`. Once task 1.9
   lands it prints "P-01 to P-03 not checked: tools/scripts/plan-policy.sh does not exist yet (task
   1.9)" on every run, which is then false, and ADR-0016 decision 1 says it goes.
2. **Replace the header's paragraph** that begins "Two jobs are deliberately partial on the
   skeleton": it says the plan policy "needs the read-only AWS role task 1.0 creates and the
   allowlist task 1.9 writes, and neither exists yet". One sentence would do: P-01 to P-03 are
   mock-provider assertions that the Terraform job's test step runs (ADR-0016).
3. **Drop `id-token: write`** from the workflow's top-level permissions, whose comment reads "For
   the AWS plan role, once task 1.9 wires it." ADR-0016 decisions 3 and 4 put no AWS credential in
   CI and need no GitHub OIDC provider, so no step will request the token, and the build and
   Terraform jobs inherit a permission they cannot use.
4. **Reword what waits on task 1.9 in the plan-generation guard**, and keep the guard exactly as it
   is: ADR-0016 decision 1 says it "remains in force". `.github/plan-secrecy.py` says plan
   generation is disabled "until task 1.9 supplies a reviewed private pipeline" (its docstring and
   its message), and the comment on its CI step says "the sentence is what task 1.9 would read
   last". Task 1.9 supplies no plan pipeline, and under ADR-0016 none is planned: a credentialed
   pipeline "needs a new decision" (decision 4), and that decision is what would lift the guard.
5. **Register a test id for the identity root's allowlist.** Q45 in
   `.scratch/overnight/questions-2026-10-15-answered.md`, answered yes, gives it its own id, P-07,
   rather than widening P-01, and notes that the edit is the integrator's because `docs/plan/` is a
   frozen export. Task 1.9 wrote the allowlist (Q42) without the id, because no document defines
   P-07 yet. Proposed row, in the shape of `docs/plan/04-tests.md`'s table, for wherever post-export
   test ids are recorded (an amendment to ADR-0016, which decides P-01 to P-03's mechanism, is one
   place):

   | ID | Check | Expect |

   | P-07 | Identity plan allowlist | One user pool, one domain, the resource servers and test users `fixtures/cognito/pool.json` lists with a generated password and a parameter per user, and no app client |

   Once it is recorded, the two runs' comments can cite it.

## Decision

Integrator, 2026-10-22, on Adam's confirmed answer,
https://github.com/adammedford/spa-platform/issues/286#issuecomment-6344559207
(Q149 to Q158, #238's grill on #286): **all five items accepted, decided at once.** Items 1 to 4
carry out ADR-0016; item 5 needed only a place for P-07.

1. **The step `Plan policy (P-01 to P-03)` is removed whole**, its comment and its
   `AWS_PLAN_ROLE_ARN` env with it. A no-op step naming the test step was rejected: it is the same
   false notice in kinder words.
2. **The header paragraph becomes one sentence:** "Plan policy (P-01 to P-03 and P-07) is
   mock-provider assertions that the Terraform job's test step runs (ADR-0016); CI holds no AWS
   credential, and plan generation stays disabled."
3. **`id-token: write` is dropped**, leaving `contents: read`. ADR-0016 decisions 3 and 4 put no
   credential and no OIDC provider in CI, so nothing can use the token.
4. **The plan-generation guard's text points at ADR-0016 decision 4, its logic byte-identical.**
   The docstring's first line, its false "There is no plan-policy implementation today" and the
   "when task 1.9 lands" after it, the refusal message, and the CI step's comment now name the new
   decision that would lift the guard, not task 1.9. The regexes, the allowed cache and the exit
   codes are unchanged.
5. **P-07 is ADR-0016's decision 7**, with the row as proposed here. A new ADR, a register created
   now and declining the id were rejected; where post-export test ids are listed is a separate
   ticket. The identity tests' comments citing P-07 are workstream 1's, on #307.

Change request 1.1's Decision gains one sentence: this request removed the placeholder that carried
its item 2's future shape, and any credentialed pipeline must meet the rule `plan-secrecy.py`
enforces. Row 1.9 is done with this request decided; the trust and execution null checks #59's
review found are #239, outside row 1.9.
