# Change request 5.5: `TestApps` no longer mirrors `app1.json`, and `dependencies.md` misses a user

- **Raised by:** workstream 5, Fixtures
- **Tasks:** 5.5, and every workstream that builds against `Platform.Testing`
- **Date:** 2026-10-13
- **Status:** open

Two integrator-owned files say something about workstream 5's fixtures that task 5.5 has made
untrue. Neither blocks 5.5 and neither is a behaviour change: both are statements a session reads
and believes.

## 1. `src/Platform.Testing/TestApps.cs` names a mirror that was never going to hold

The doc comment says:

> The defaults mirror `fixtures/apps/app1.json`: a host under the allowed suffix, one upstream, no
> content security policy additions, an eight-hour session.

`fixtures/apps/app1.json` now exists, and four of those five claims do not match it.

| Claim | `TestApps.Entry` default | `fixtures/apps/app1.json` |
| --- | --- | --- |
| A host under the allowed suffix | `app1.spa-poc.test`, from `HostSuffix = ".spa-poc.test"` | `app1.spa-poc.test:8443`. `Policy:AllowedHostSuffixes` in `contracts/platform-config.example.json` is `[".spa-poc.test:8443"]`, so the double's host would be refused by the validator of task 2.1 |
| One upstream | `Apis` defaults to empty | Two: `orders` and `reports`. The 5.5 row requires the second one, because N-17 sends app 1's token to `reports` through it |
| No content security policy additions | No `csp` | No `csp`. This one holds |
| An eight-hour session | 480 minutes | 480 minutes. This one holds |
| The issuer | `"primary"` | `cognito-poc`, which is the issuer `contracts/platform-config.example.json` configures |

The mirror was written at task I-3, before any fixture existed, so this is drift rather than a
mistake. It matters because the comment invites a workstream to treat the double's defaults as the
real app 1, and three of the differences are the kind that pass in a component test and fail in the
composed suite: a host the validator refuses, an app with no upstream at all, and an issuer that
platform configuration does not name.

### What workstream 5 suggests

Keep `TestApps`' defaults as they are and stop claiming the mirror. The defaults are good defaults
for a double — an app with no upstream is the right starting point for a test that adds the one
upstream it cares about — and changing them would churn every workstream's tests for nothing.

So: replace the mirror sentence with something that does not promise equality, for example "The
defaults are the smallest entry the interfaces accept; pass only what the test cares about. They are
not a copy of `fixtures/apps/app1.json`, which carries the suffix with its port, two upstreams and
the configured issuer."

The alternative — making the double equal to app 1 — is the one workstream 5 does not recommend:
`HostSuffix` would have to carry `:8443`, `Apis` would have to default to two upstreams, and every
existing test that assumes an empty `Apis` would change. The double would also then have to follow
every later edit to a fixture, which is a coupling nobody asked for.

## 2. `docs/dependencies.md` does not list `Fixtures.Tests` as a user of `JsonSchema.Net`

The row reads:

> | JsonSchema.Net | ... | Schema tests, `spactl` |

`fixtures/Fixtures.Tests` is now a third user: task 5.5's "done when" is that each definition
validates against `contracts/app-definition.schema.json`, which needs a schema evaluator.

No package or version changed — `JsonSchema.Net` is already in `Directory.Packages.props` and the
reference carries no version, as AGENTS.md requires — so this is not the "a new package or a
different version" route. It is one stale column in a file workstream 5 may not edit.

## Decision asked for

1. Replace or correct the mirror sentence in `src/Platform.Testing/TestApps.cs`, or tell workstream
   5 to change the fixtures to match the double instead and say what should give: the host's port,
   the second upstream that N-17 needs, or the configured issuer.
2. Add `Fixtures.Tests` to the `JsonSchema.Net` row in `docs/dependencies.md`.

Nothing is blocked meanwhile. Task 5.5 is complete and its suite is green; both items are statements
about the fixtures rather than anything the fixtures need.
