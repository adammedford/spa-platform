# Change request 4.2: give `AccessTokenResult` the provider-unavailable outcome ADR-0005 says it has

- **Raised by:** workstream 4, API and security, during task 4.2
- **Tasks:** 4.2 (the proxy answers each outcome), 3.8 (the token source returns it)
- **Date:** 2026-10-16
- **Status:** decided, 2026-10-16. See the Decision section below.

## The gap

ADR-0005's consequences say: "The contracts had no outcome for an unreachable provider;
`AccessTokenResult` and the error table each gained one (503 `idp_unavailable`, session kept)."
Evidence T-A9 and T-A15 (`docs/plan/07-evidence.md`) name the same need and assign it to task I-6.

Neither gained one. `src/Platform.Abstractions/IAccessTokenSource.cs`, frozen by `contracts-v1`, has
three outcomes: `Token`, `Unauthenticated` and `SessionEnded`. `contracts/http-contract.md` -> Errors
has no 503 row and no `idp_unavailable` code.

Task 3.8's row says "any other failure leaves the session and fails the call", so the token source
needs a way to say "the provider could not be reached, the session stands" that is neither
`Unauthenticated` (which tells the browser to log in again) nor `SessionEnded` (which the browser
reads as the session being gone).

## The change

1. `AccessTokenResult` gains `public sealed record ProviderUnavailable : AccessTokenResult;` (name
   the integrator's), documented as "the provider could not be reached or failed other than with
   `invalid_grant`; the session is kept".
2. `contracts/http-contract.md` -> Errors gains `503 | idp_unavailable | The identity provider could
   not be reached to refresh the token; the session is kept`.
3. `FakeAccessTokenSource` needs nothing: `ForApp(appId, result)` and `Result` already take any
   outcome.

## What task 4.2 did meanwhile

The proxy answers the three outcomes that exist. Any other `AccessTokenResult` is never forwarded:
`AccessTokenStep` throws, so the browser gets a 500 and the upstream sees nothing. When this request
is decided, the proxy adds one case, 503 `idp_unavailable` with no rule id (it is not a rejection),
and a test beside the two 401 tests in `tests/Platform.Proxy.Tests/AccessTokenStepTests.cs`.

## Why this is a request rather than an edit

`src/Platform.Abstractions` and `contracts/` are the integrator's, and both parts froze at G1b with
the `contracts-v1` tag (`contracts/README.md` -> What G1b froze).

## Decision

Accepted as asked, on Adam's acceptance of the overnight recommendation (Q25, 2026-10-16).

- `AccessTokenResult` gains `ProviderUnavailable`, the name the request proposed. It is a new type
  that changes no existing signature, so `contracts/README.md` lets it land between gates; nothing
  built against the frozen record has to change to keep compiling, and the proxy's step already
  refuses an outcome it does not know.
- `contracts/http-contract.md` → Errors gains `503 | idp_unavailable`, and ADR-0005's consequence
  line now records the date it became true rather than reading as if it always had been.
- It is not a rejection: no rule id, `rule` stays null on the request line, as for the 401 the
  token step answers when there is no session.

What follows, one ticket each: task 3.8 returns `ProviderUnavailable` where it throws
`IdentityProviderUnavailableException` today, and task 4.2 answers it with 503 `idp_unavailable`
and stops forwarding when no `IAccessTokenSource` is registered. Workstream 6 proves the composed
503 under task 6.2.
