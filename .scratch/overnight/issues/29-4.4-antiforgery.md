Seams (chosen by implementer):
- The HTTP pipeline: `AddPlatformSecurity` + `UsePlatformAntiforgery` in a host with stand-ins for stage 1 (real), stage 4 (`SettableAppFeature` by Host header, both apps in one host so one key ring signs both) and stage 7 (user from a test header, authenticated identity with `sub`).
- `ICsrfTokens` as resolved from DI, exercised through stand-in `/bff/session` (Issue) and `/bff/logout` (Clear) endpoints.

Decided by implementer:
- An unsafe `/api` request with no session is checked, and refused 403 `csrf_failed`, rather than passed on for the proxy to answer 401. No anonymous pair can exist, so this fails closed; an expired-session SPA gets 403 instead of 401 on a write.
- `SuppressXFrameOptionsHeader = true`: the contract's header set has no X-Frame-Options; framing is stage 5's `frame-ancestors 'none'`.
- The framework's `UseAntiforgery()` is not called in stage 9, so a form-bound `/bff/logout` endpoint would not be made to demand a token.
- The stub user is built in the test project rather than requested in `Platform.Testing`.
- The test host uses an ephemeral data-protection provider, so tests write no key ring under the user profile.

Note for later: antiforgery tokens are data-protected, so whichever key ring the composed gateway ends up with (identity's concern) also governs CSRF tokens across instances.

### Standards (CODING_STANDARDS.md + smell baseline)
1. **Fixed — incomplete vendor claim (comment).** `UsePlatformAntiforgery`'s comment said not calling `UseAntiforgery` spares a form-bound `/bff/logout` a token demand. Verified against `Microsoft.AspNetCore.Routing.dll` (10.0.12) resource string: an endpoint with antiforgery metadata throws "contains anti-forgery metadata, but a middleware was not found that supports anti-forgery" when `UseAntiforgery` did not run, so such an endpoint is a 500, not a pass. Also verified `Microsoft.AspNetCore.dll` holds no antiforgery auto-wiring, so the implementer's "not called" holds. Comment now says WS3 must use `DisableAntiforgery()` or read the form itself, with the learn.microsoft.com link.
2. **Fixed — vendor behaviour without citation (judgement).** Added source links for `IsRequestValidAsync` treating GET/HEAD/OPTIONS/TRACE as valid, the `__Host-` prefix rule behind the deletion attributes (RFC 6265bis), and the `sub`-first claim uid the test host relies on.
3. **Fixed — Duplicated Code (judgement).** RE3b and the pre-logout N-06 test re-implemented a weaker refusal check (status, reached count, one log line) and skipped the `csrf_failed` code and the N-16 canary checks. `AssertRefusedAsync` now has an `AssertRefusedAfterAsync(reachedBefore)` form used by both.
4. **Fixed — Primitive (judgement, trivial).** `"csrf.token"` is now a named `Rule` constant, as in `MethodAllowlist`.
- Rejected: literal `"__Host-spa-csrf="` / `"X-CSRF-TOKEN"` in tests. That is the right direction for "a guard reads the thing it guards": the tests pin the contract literal against the source constant, so a rename fails them.
- Rejected: `CsrfTokens` as Middle Man. It adapts `IAntiforgery` to the frozen `ICsrfTokens` contract and owns `Clear`, which the framework lacks.
