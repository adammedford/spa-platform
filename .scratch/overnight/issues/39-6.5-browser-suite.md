## Answer

**Landed** on `task/6.5-browser-suite` (head 7acfdf6, forked from overnight/2026-10-16 at d0e81ad), all under `tests/e2e`:

- `Stack/`: `LocalStack` (the hermetic cell from 6.1 with a session required, per test), `TlsLoadBalancer` (an HTTPS stand-in for the ALB on loopback that forwards through the harness's `LoadBalancerTransport`, records every exchange with its body, can hold a request such as a login's callback, and serves hostile pages), `Chromium` (headless Chromium via Microsoft.Playwright 1.63, installed by the suite and launched with `--host-resolver-rules` so every app host reaches the stand-in), `Profile` (one browser context: sign in, stop at callback, `fetch()` from the page, cookies), `Contract` (a copy of the negative suite's contract reader), `TokenShape`.
- `Functional/`: F-01, F-02 (`SignInTests`), F-03, F-04 (`SessionLifecycleTests`), F-05 (`ExposureTests`, web storage included), F-06 (`ShellTests`: app 2's `data:` image loads and app 1's is refused by the browser, the fallback matrix, a release switch and switch back), F-07 (`OnboardingTests`, the third SPA) and F-08 (`ApiRouteTests`).
- `Negative/`: N-01, N-19, N-27 (`SessionTests`), N-03, N-04, N-05 (`LoginTests`), N-06 (`CsrfTests`), N-07 (`OriginTests`: a sibling page sends `same-site` with the victim's cookie attached, and a page elsewhere sends `cross-site`; preflight included), N-08 (`HostTests`), N-10, N-17 (`ApiTests`), N-23, N-24 (`HeaderTests`, which also checks that Chromium refuses to frame the shell), N-25 and N-26 (`CookiePlantingTests`).

That is 34 tests. A full e2e run takes about 12 s.

**Seams (chosen by implementer):**
- **The browser:** what a page, its script or the user does in real Chromium. This catches what only a browser enforces: Fetch Metadata, the `__Host-` prefix, `SameSite`, CSP and `frame-ancestors`. It misses requests no browser will send, which go to the raw client below.
- **The load balancer's record:** the exact bytes the browser received. F-05 and N-23 search it, and N-24 reads its headers.
- **The raw client through the same load balancer:** an absent `Sec-Fetch-Site`, a foreign `Origin`, a case-variant cookie and a spoofed `X-Forwarded-Host` on an unknown host.
- **The gateway log:** the D tier's evidence. It gives the rule ids and F-03's refresh line.
- **The provider's and the mock API's records:** where the row names them.

**Findings while building:**
- A Playwright route cannot stand in for the ALB. A routed request is paused before Chromium adds `Sec-Fetch-*`, so the gateway refused the login. A route also sees only the first request of a redirect chain. That is why the stand-in is a real TLS listener.
- Chromium 153 refuses case variants of `__Host-` as well as the exact name. N-25's gateway half is therefore shown with the raw client.
- Chromium does not apply `form-action` to the logout's redirect to the provider. This answers the open question in contracts/http-contract.md for the local Chromium. F-04 goes through the provider's end-session endpoint. **(Wrong; corrected in Review: Chromium 153 does apply it.)**

**Mutation:** letting the request gate accept `Sec-Fetch-Site: same-site` failed 1 of 3 N-07 tests, the sibling page's. The mutation was reverted.

**Gate:** GREEN. Last test summary: `total: 1500, failed: 0, succeeded: 1500, skipped: 0` (log/6.5-implement.txt).

**Decided by implementer:**
- The local stand-in is an in-process TLS listener with a self-signed certificate made per run. The browser context ignores certificate errors, standing in for the local certificate authority.
- Hostile pages (a sibling under the app domain, and `attacker.example`) are served by the stand-in on loopback rather than by Playwright routes. Fetches from a route-fulfilled page to an app host never left Chromium, most likely because of local network access rules.
- The `%2e%2e%2F` escape variant of N-10 is left to the hermetic raw socket. The local stand-in forwards through `System.Uri`, which unescapes `%2e`.
- AWS-only clauses are not written as tests that skip locally (CODING_STANDARDS.md, "A test that skips on the machine it runs on"). They are listed below instead.

### Standards (CODING_STANDARDS.md, smell baseline)

1. **Wrong vendor claim in F-04 (fixed, verified).** `SessionLifecycleTests` said Chromium does not
   apply `form-action` to the logout's redirect. The test could not show that, because the policy
   already allows the provider origin. Verified by a mutation in the stand-in load balancer that
   rewrote `form-action` to `'self'`: F-04 failed 1 of 1, with the page staying on "Fixture SPA app1".
   So Chromium 153 does apply it, as contracts/http-contract.md says, and the provider origin in
   `form-action` is load-bearing. The comment now says so. No change request is needed, because the
   contract already says this.
2. **Duplicated Code: navigation recorder (fixed).** The same `Page.Request` handler appeared four
   times (SignIn, SessionLifecycle, Onboarding, Session tests). It is now `Profile.RecordNavigations()`.
3. **A comment naming what another row owes (fixed).** The F-07 summary said the AWS clauses "are task
   6.9's". Now it says why they are absent. That belongs in Outstanding, which already lists it.
4. **Duplicated Code: `Stack/Contract.cs` (skipped).** It is a verbatim 220-line copy of
   `Gateway.SecurityTests/Negative/Contract.cs`. Skipped because the repo chose this on purpose
   (the suites share the harness and nothing else), and moving it into `Gateway.TestHarness` would
   touch two other suites. Worth a ws6 follow-up.
5. **Vendor citation for the macOS PKCS#12 round trip in `TlsLoadBalancer.SelfSigned` (skipped).**
   The comment states the behaviour without a link. This is low value, and I had no verified URL
