## Answer

Branch `task/2.5-secret-source`, commit 6d6ee82 (fork a5059b8).

What landed:
- `src/Platform.Registry/ParameterStoreClientSecretSource.cs`: `IClientSecretSource` over Parameter Store. `ssm:{name}:{version}` is read with `GetParameter`, `Name = "{name}:{version}"` (the version selector, cited) and `WithDecryption = true`. Values are held in a concurrent map by reference and never re-read; an answer for another version is refused; a malformed reference fails without I/O; one unreadable reference fails alone (task 2.2's "one app, not all") and is retried by the next preload; cancellation propagates and marks nothing failed. `Get` does no I/O and distinguishes "not preloaded" from "could not be read (reason)".
- `src/Platform.Registry/PlatformRegistryExtensions.cs`: `AddPlatformRegistry` registers the source as a singleton and `IAmazonSimpleSystemsManagement` with `TryAddSingleton`, built on first use from the SDK's default region and credential chains.
- `src/Platform.Registry/Platform.Registry.csproj`: references `AWSSDK.SimpleSystemsManagement` (already pinned, assigned to this project in docs/dependencies.md; no change request needed).
- Tests in `tests/Platform.Registry.Tests`: `ParameterStoreClientSecretSourceTests` (17 cases), `RegistrationTests` (2), `StubParameterStore` (subclass of the SDK client overriding `GetParameterAsync`), `ListLoggerProvider` (copied from Platform.Security.Tests).
- N-16 here: `No_value_appears_in_a_log_line_or_an_exception` runs a canary through success, not found, an SDK exception whose message carries the canary, a wrong version and a not-preloaded read, then searches every log line and every `exception.ToString()`. Mutation-checked: logging `ex.Message` instead of the error code makes it fail.

Seams (chosen by implementer):
- `IClientSecretSource` as implemented by `ParameterStoreClientSecretSource`, with `IAmazonSimpleSystemsManagement` as the injected boundary (stubbed by subclassing the SDK client; no mocking package exists).
- `AddPlatformRegistry`'s registration, resolved from a built host with the SDK client supplied.

Decided by implementer:
- No eviction: version-pinned values are immutable and the old reference must stay readable for the live snapshot until a swap; the cache grows only by versions referenced in the process's life.
- A failed reference is retried on the next preload rather than cached as failed.
- Failures carry the reference and the SDK error code only; the SDK exception is not logged or chained as an inner exception.
- A response whose version differs from the pinned one is refused.
- Preload reads at most four parameters concurrently (GetParameter default throughput 40 TPS).
- The SDK client is registered with TryAdd and built lazily, so hosts that never read a secret need no AWS region or credentials.

Gate: GREEN (`.scratch/overnight/log/2.5-implement.txt`): total 565, failed 0, succeeded 565, skipped 0.

Note for task 2.2: the SDK client registration is lazy, so the composed gateway builds no SSM client today. Once 2.2 resolves `IClientSecretSource` in the composed host, the `Gateway.*` test hosts need a fake `IAmazonSimpleSystemsManagement` or `IClientSecretSource` registered (a later `AddSingleton` wins over the `TryAdd`), or the client will be built with no region.

- **Fixed (verified by a run): a vendor-behaviour comment was wrong, and the code relied on it.** The `AmazonClientException` catch said it covered "no network". A probe that called a real `AmazonSimpleSystemsManagementClient` at a closed loopback port (MaxErrorRetry 0) got a bare `System.Net.Http.HttpRequestException` (inner `SocketException`), not an `AmazonClientException`. The comment now records what was observed.
- Skipped (judgement call, Duplicated Code): `tests/Platform.Registry.Tests/ListLoggerProvider.cs` is a copy of the one in `Platform.Security.Tests`. Sharing it means putting it in `Platform.Testing`, which the integrator owns. Two small test helpers do not justify a change request.
- Skipped (guard reads the thing it guards): the refused-reference theory lists bad references inline and does not read the schema pattern. `TryParse` is only the guard for callers outside the registry. `RegistryValidator` owns the schema check, and its tests already read the schema.
- Otherwise clean. Comments cite the plan row, ADR-0003, N-16 and AWS documentation. The N-16 assertions can fail: the implementer checked this with a mutation, and the new test asserts that the SDK message is absent.

### Spec (ticket, plan row 2.5, contracts/README.md `clientSecretRef` row, IClientSecretSource)
- **Fixed (verified by a run): one transport failure failed the whole batch.** `IClientSecretSource.PreloadAsync` promises that "a reference that cannot be read does not fail the batch", and the contract row and task 2.2 say one unreadable secret costs one app, not all. Before the fix, an `HttpRequestException`, or a `TaskCanceledException` that the caller's token did not raise (an HTTP timeout), escaped `LoadAsync`. That aborted `Parallel.ForEachAsync` for every reference and handed the SDK's message to the caller, which is a possible N-16 path once task 2.2 logs it. The new test `A_transport_failure_on_one_reference_is_a_failure_of_that_reference` (network and timeout cases) failed against 6d6ee82 with both exceptions propagating. After the fix it passes. Every non-cancellation exception now fails only its own reference and is reported by type name only. Cancellation by the caller's token still propagates.
- No missing requirements and no scope creep. The concurrency of 4, no eviction, and retrying a failed reference are all decisions the implementer documented, and each is consistent with the plan.
