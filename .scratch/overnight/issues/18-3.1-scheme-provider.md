## Answer

**Landed** on `task/3.1-scheme-provider` (commit a1f7e12, forked from bf36a81):

- `src/Platform.Identity/RegistrySchemeProvider.cs`: the host-scoped `IAuthenticationSchemeProvider`
  (ADR-0001), ported from the spike's `RegistrySchemeProvider` under `Platform.Abstractions.SchemeNames`.
  It reads the app and snapshot from `IAppFeature` (never the registry directly), returns that app's
  scheme pair as defaults (challenge `oidc:{appId}`, everything else `cookie:{appId}`), its OIDC scheme
  as the only request-handling scheme, nothing for any other name (ordinal, exact), nothing when no
  app is pinned, caches the pair per snapshot (a `ConditionalWeakTable` keyed by snapshot), and throws
  `NotSupportedException` on `AddScheme`/`RemoveScheme` (`TryAddScheme` therefore returns false).
- `src/Platform.Identity/PlatformIdentityExtensions.cs`: `AddPlatformIdentity` adds the HTTP context
  accessor, replaces the scheme provider, and registers the framework's
  `PostConfigureCookieAuthenticationOptions` unbound to any scheme. Numbered stage mentions replaced
  by entry-point names (CODING_STANDARDS, ADR-0018).
- `tests/Platform.Identity.Tests/SchemeProviderTests.cs` (S-B8, R-B6, defaults, caching, AddScheme)
  and `HandlersPerRequestTests.cs` (S-A7, R-A6, S-F1 through the framework's `AuthenticationMiddleware`).

**Seams (chosen by implementer):**
1. `IAuthenticationSchemeProvider` as resolved from the container after `AddPlatformIdentity`, on an
   `HttpContext` carrying a `SettableAppFeature` (the stand-in for host resolution). Catches what
   each name/default resolves to per host; misses how the framework uses it.
2. The framework's own `AuthenticationMiddleware` over those services, with
   `IAuthenticationHandlerProvider` decorated to record every handler handed out on one request.
   Catches handlers built per request (one `OpenIdConnectHandler`, the host's own); misses timing.

**Mutations run** (each reverted): request-handler schemes returning every snapshot app's OIDC
scheme failed 1 of 17; foreign `oidc:`/`cookie:` names resolving failed 4 of 17; both together
(stock-like) failed 7 of 17, including both middleware handler-count tests; no cache failed 1 of 17;
a cache that survives a swap failed 1 of 17.

**Gate:** GREEN, `.scratch/overnight/log/3.1-implement.txt`: total 1226, failed 0, succeeded 1226.

**Decided by implementer:**
- `AddPlatformIdentity` registers `PostConfigureCookieAuthenticationOptions` in 3.1: without it the
  middleware's default authenticate throws a NullReferenceException in `CookieAuthenticationHandler`
  on every pinned request (observed red). `OpenIdConnectPostConfigureOptions` is NOT registered here:
  it throws without an authority or configuration manager, so it belongs with task 3.2's named options.
- S-F1's timing half (142 to 172 microseconds) is not asserted in a component test; the handler
  count at 303 apps and per-app challenge scheme are. "Any app can log in" is proven only as far as
  the default challenge scheme; the login itself needs 3.2's options.
- `SchemeNames` has no `TryParse`; 3.1 does not need one, so no change request.
