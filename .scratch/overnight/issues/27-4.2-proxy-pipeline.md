## Answer

- `src/Platform.Proxy/AccessTokenStep.cs`: a step in YARP's proxy pipeline, ahead of `UpstreamFailure`. `Token` puts the token on the request as an internal feature; `Unauthenticated` gives 401 `unauthenticated`, `SessionEnded` gives 401 `session_ended`, both problem bodies, no redirect, nothing forwarded, no rule id. Any other outcome throws (500), so nothing goes upstream without a token.
- `src/Platform.Proxy/UpstreamHeaders.cs`: transforms on every generated route (`AddTransforms` in `AddPlatformProxy`). Request: removes `Cookie`, `Authorization`, `X-CSRF-TOKEN`, `Forwarded`, `Via`, `X-Real-IP` and every `X-Forwarded-*` / `X-Original-*` (names read through `NonValidated`), attaches `Authorization: Bearer <token>`, then sets only `X-Forwarded-For`, `-Proto` and `-Host` (`UseDefaultForwarders = false`, so no `X-Forwarded-Prefix`). Response: `Set-Cookie` removed with `ResponseCondition.Always` (T-C7), `Access-Control-*` removed by prefix on every status.
- `src/Platform.Proxy/PlatformProxyExtensions.cs`: wiring only, same signatures.
- Tests in `tests/Platform.Proxy.Tests`: `AccessTokenStepTests` (N-19 for `/api`, session_ended, no rule id, per-app token, skeleton with no source), `RequestHeaderTests` (N-11, T-C3: 19 planted headers, the exact three forwarding headers, a control header that passes), `ResponseHeaderTests` (N-12, T-C7 on 200/500/401, plus the gateway's CSP with `UsePlatformSecurityHeaders` in front). `ProxyHost` gained a host-resolution stand-in, a `FakeAccessTokenSource` (default token so routing tests still forward) and `ProxyHostOptions`. `PlantingUpstream` is test-local because `EchoResponse` has no headers. The test project now references `Platform.Security` (ws4's own; A-03 binds src projects only).

Seams (chosen by implementer): (1) `AddPlatformProxy` + `MapPlatformProxy` on a loopback `ProxyHost` with `FakeAccessTokenSource` and `EchoUpstreamListener`, observed as what the upstream received and what the client got back; (2) the same host behind `PlantingUpstream`, optionally with `UsePlatformSecurityHeaders` in front, for the response clauses.

Mutations: `ResponseCondition.Success` in place of `Always` failed 3 of 64 (the 500 and 401 cases); an empty prefix list failed 11 of 64; `session_ended` written as `unauthenticated` failed 1 of 64.

- The token call gets `CancellationToken.None`, not `RequestAborted` (T-B15, T-B16).
- Neither 401 writes a rule id (contracts/telemetry.md: not a rejection; `auth.session` belongs to the shell gate).
- An `AccessTokenResult` outside the three frozen outcomes throws (500) rather than forwarding.
