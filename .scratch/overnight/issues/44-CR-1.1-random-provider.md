### Facts established first (read from the repo, not asked)

- **The provider is used where the request says.** `infra/modules/idp-cognito/main.tf:99` declares `resource "random_password" "test_user"`. Its `result` feeds `aws_cognito_user.this.password` (line 123) and `aws_ssm_parameter.test_user_password.value` (line 142). `infra/modules/idp-cognito/versions.tf` and `infra/envs/poc/idp/versions.tf` both require `hashicorp/random` at `~> 3.7`. Both tests use `mock_provider "random" {}`.
- **The lock files agree with the proposed row.** `infra/modules/idp-cognito/.terraform.lock.hcl` and `infra/envs/poc/idp/.terraform.lock.hcl` both pin `registry.terraform.io/hashicorp/random` at version `3.9.1` with constraints `~> 3.7`. `infra/bootstrap` and `infra/envs/poc/apps` pin `hashicorp/aws` only.
- **"1.8 if it generates anything" is closed.** Task 1.8 merged on this branch (`9527dcb`), and the apps root's lock file has no `random` provider. Only the identity module and root need the row.
- **The request's schema claims hold.** I ran `terraform providers schema -json` in `infra/modules/idp-cognito` (cached providers, no network, no apply). In `hashicorp/aws` 6.68.0, `aws_cognito_user.password` is `sensitive` and not `write_only`. `aws_ssm_parameter.value_wo` is `write_only`. `aws_secretsmanager_random_password` exists as both an ephemeral resource and a data source. In `hashicorp/random` 3.9.1, `random_password.result` is `sensitive`, and `random_password` also exists as an ephemeral resource. Because the Cognito user resource stores the password, the password is in state whichever generator is used.
- **The licence is MPL-2.0 for both providers.** The `LICENSE.txt` in each cached provider directory reads "Mozilla Public License Version 2.0", with copyright IBM Corp. The `hashicorp/aws` row in `docs/dependencies.md` states no licence today. The NuGet table has a Licence column and the Terraform table does not.
- **Why the floor is 3.7 is not established.** Nothing in the repository explains why the floor is `~> 3.7` rather than a lower 3.x. I did not confirm from release history which 3.x version first offered every attribute the module uses. The constraint is consistent across both `versions.tf` files and both lock files. A fresh resolve of `~> 3.7` picks the newest 3.x anyway, as the request's own `terraform init` showed.
- **State protections are as stated.** `infra/bootstrap/state.tf` keeps the state bucket private (public access block), versioned, SSE-S3 encrypted and with `BucketOwnerEnforced`. The request calls it "TLS only". Commit `c223aa7` ("the plan role can read the test users") shows that the CI plan role can read state, and so can read the passwords.
- **The file's header is dated.** `docs/dependencies.md` opens "Checked on 11 October 2026". The request was checked on 13 October 2026. The Sources section lists the `hashicorp/aws` registry page and nothing for `random`.
- **Precedent for closing.** `contracts/changes/i-7-...md` and `1.6a-...md` use `- **Status:** decided, <date>. See the Decision section ...` followed by `## Decision` headed "Integrator, <date>." Q46 (answered yes) applies the same form to CR-5.5.

### Round 1

❓ **Q1** - **Add the row as proposed?** `| Provider hashicorp/random | 3.9.1 | Constrain to ~> 3.7. MPL-2.0, published by HashiCorp. Task 1.1's test-user passwords |`

➡️ Yes. Both lock files pin it, both `versions.tf` files require it, and the table is meant to list what a build resolves. *Adopted.*

---

❓ **Q2** - **Accept a managed `random_password`, which keeps the password in state, over the AWS provider's generators?**

➡️ Yes. The schema check confirms the request's reasoning: `aws_cognito_user.password` is not write-only in 6.68.0, so an ephemeral value cannot feed it, and the user resource puts the password in state whatever generates it. The data-source alternative churns every plan and needs `secretsmanager:GetRandomPassword` on the plan role. *Adopted.*

---

❓ **Q3** - **Accept the `~> 3.7` constraint as written, without asking workstream 1 to justify the floor?**

➡️ Yes. The floor only matters to a resolve that cannot reach a newer 3.x, and the lock files pin 3.9.1 regardless. The reason for 3.7 in particular is unverified, so the Decision should not state one. *Adopted.*

---

❓ **Q4** - **Keep the licence in the Note column, as the request words it, and add "MPL-2.0" to the `hashicorp/aws` row's Note at the same time?**

➡️ Yes. The Terraform table has no Licence column, and the NuGet table records every licence. Both cached provider licence files read MPL-2.0. One added word on the `aws` row makes the two rows consistent. *Adopted.*

---

❓ **Q5** - **Close the request as I-7 was closed (Q46's form): Status `decided, <date>`, a `## Decision` section headed "Integrator, <date>.", and the row added in the same commit?**

➡️ Yes. It is a dependencies-table edit with no interface change, so it needs no gate. *Adopted.*

### Round 2 (frontier after adopting Q1 to Q5)
