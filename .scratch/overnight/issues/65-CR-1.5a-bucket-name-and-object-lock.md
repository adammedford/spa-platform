### Facts established before round 1 (looked up, not asked)

- **No platform bucket exists yet.** In account `146873694665`, `ListBuckets` returns only
  `spa-platform-poc-tfstate-146873694665`, and `HeadBucket` returns 404 for both
  `spa-platform-poc` and `spa-platform-poc-146873694665`, so neither name is held by any account
  today. Bootstrap *is* applied (local, untracked `infra/bootstrap/terraform.tfstate`, region
  `us-east-2`, serial 14). It has no teardown role yet. The platform root has not been applied, so
  renaming the bucket costs nothing now. After the first apply, a rename means a new bucket and a
  re-seed.
- **The account-qualified pattern is already the house style for globally unique names.** The state
  bucket is `spa-platform-<cell>-tfstate-<account id>` (`infra/bootstrap/README.md`, "S3 names are
  globally unique"). The managed-login prefix defaults to `spa-platform-<cell>-<account id>`
  (`infra/envs/poc/idp/variables.tf`). Only the platform bucket (`infra/modules/cell/storage.tf:16`,
  `local.name_prefix`) is unqualified.
- **ADR-0014 already calls the account-qualified name "the intended default"**, but it does not
  decide it: CR 1.5's decision lists it as a follow-up. That is why this request is a decision and
  not just an edit to the examples.
- **The examples are coupled to the module in prose.** The `bucket_name` description in
  `infra/modules/cell/variables.tf` says the empty default "is what
  contracts/infra-outputs.example.json and Registry:Bucket … both show". If the examples change, that
  comment goes stale unless workstream 1 changes it too.
- **No test pins the example value.** The one C# literal, at `tests/Contracts.Tests/PlatformConfigurationTests.cs:38`,
  is a misspelled-key negative case. Both proposed values match the `bucketName` pattern
  `^[a-z0-9][a-z0-9.-]*[a-z0-9]$` and fit within 63 characters. The module test at
  `module.tftest.hcl:511` exercises the `bucket_name` override.
- **The same file has a second stale rendered value that the request does not mention.**
  `infra-outputs.example.json` → `cognitoDomain` reads `spa-poc.auth.us-east-1.amazoncognito.com`,
  and `platform-config.example.json` → `Issuers.cognito-poc.BrowserOrigin` repeats it. The idp root
  defaults to `spa-platform-<cell>-<account id>`, and its own test asserts
  `spa-platform-poc-111122223333.auth.us-east-1.amazoncognito.com`. So the request's claim that
  "they are the only rendered instance of the name anywhere in the contracts" holds for the bucket,
  but the cognito domain has the same defect.
- **S3 has offered account regional namespaces since March 2026.** A general purpose bucket named
  `<prefix>-<account id>-<region>-an` and created with `x-amz-bucket-namespace: account-regional`
  "can never be re-created by another account". The feature is available in every Region except
  Bahrain and UAE (S3 User Guide, "Namespaces for general purpose buckets", read 2026-10-16). A name
  that is merely account-*qualified* in the global namespace gives no such guarantee: an account id
  is not a secret, so anyone can create `spa-platform-poc-146873694665` first. The pinned provider,
  `hashicorp/aws` 6.68.0, contains a `s3.bucketNamespace` symbol. The exact Terraform argument name is
  workstream 1's to confirm.
- **Object Lock protects versions, not keys.** A simple `DELETE` (no version id) on a locked object
  returns 200 and makes a delete marker the current version, and delete markers are not
  WORM-protected (S3 User Guide, "Object Lock considerations" and "How deletes work with S3 Object
  Lock", read 2026-10-16). ADR-0014 records that a conditional `If-None-Match: *` write succeeds when
  the current version is a delete marker. So Object Lock *without* the bucket policy's delete deny
  still lets a principal replace a release in two steps. The old version survives as a noncurrent
  version, but the gateway reads the current one. The change request does not give this reason, and
  it is the strongest one: Object Lock does not deliver ADR-0009's guarantee on its own.
- **Teardown has to find the bucket without `outputs.json`.** ADR-0013 and ADR-0014 both reject
  reading a teardown input from an apply artefact, because the artefact may be stale or gone. The
  platform root's state is remote (S3 backend), and `terraform destroy` needs it in any case.
- **Accepted ADRs are amended in place, with a dated note on the Status line.** Precedent: ADR-0005's
  "Amended 2026-10-16 by ADR-0017". The README asks for a new ADR or a status change only when a
  decision is *revised*.

### Concrete scenarios used to test the terms

1. **Second account.** A colleague's sandbox account applies cell `poc`. Under today's default the
   apply fails with `BucketAlreadyExists`. Under either qualified form it succeeds.
2. **Teardown, then redeploy (task 6.9).** Teardown deletes `spa-platform-poc-146873694665`.
   Before the redeploy, any other account creates that name. The redeploy fails, and an operator
   holding a stale `outputs.json` could run `spactl` against a bucket the platform does not own.
   Under the account regional namespace, nobody else can create the name.
3. **The `bucket_name` override is set and `teardown.sh` derives the name.** The script empties a
   bucket that does not exist, `terraform destroy` then hits the non-empty real bucket, and teardown
   fails at G3. If any consumer *derives* the name, the override breaks it.
4. **A cell named `a-tfstate`.** Under the global account-qualified form, its platform bucket
   `spa-platform-a-tfstate-<account id>` is exactly cell `a`'s state bucket. Under the regional
   form, the `-<region>-an` suffix keeps the two apart.
5. **Object Lock instead of the delete deny.** A writer sends a simple `DELETE` to
   `apps/app1/releases/1.0.0/index.html`, which creates a delete marker, then a conditional `PUT`,
   which succeeds. The live release is replaced and the lock never triggers.
6. **Object Lock in compliance mode, retention one day.** `teardown.sh` runs, cannot delete any
   version under `apps/`, `terraform destroy` fails, and P-05 stays red for a day. With a longer
   retention it stays red for longer.

### Round 1

❓ **Q1** - **Which default name does the platform bucket get?** Options:
(a) keep `spa-platform-<cell>`. It is unqualified, so a second account collides (scenario 1).
(b) `spa-platform-<cell>-<account id>` in the global namespace, as the request proposes. This
matches the state bucket and the managed-login prefix. It stops accidental collision, but anyone who
knows the account id can claim the name first, which is a real risk across teardown and redeploy
(scenario 2).
(c) `spa-platform-<cell>-<account id>-<region>-an` in the S3 account regional namespace. No other
account can ever create it, so scenarios 1, 2 and 4 all disappear. Costs: the name is longer (see
Q9), and it breaks the house pattern that the state bucket follows.

➡️ (c). Adopted provisionally. The fallback is (b) if workstream 1 finds that the pinned provider
cannot set the namespace. It costs nothing until the first platform-root apply, and the
redeploy-squatting window is one that task 6.9 opens on purpose.

## Proposed glossary / ADR

**Glossary terms** (proposed, not written to `GLOSSARY.md`):

- **Platform bucket**: the cell's one private S3 bucket, holding the registry and every release.
  The brief's "one private bucket". _Avoid_: "the bucket" where the state bucket could be meant,
  "assets bucket", "release bucket".
- **State bucket**: the bootstrap root's bucket that holds Terraform state for every root. It
  outlives teardown and holds no platform data. _Avoid_: "backend bucket", "the second bucket".
- **Teardown role**: the break-glass principal, one per cell, that alone may delete under a
  release prefix. It deletes and never writes. _Avoid_: "admin role", "the operator" (the operator
  destroys the roots, the teardown role empties `apps/`).
- **Release** (sharpen the existing entry): replace "an immutable S3 prefix" with "a write-once S3
  prefix", adding: no principal that can write it can delete it. It is not WORM retention. _Avoid_:
  "immutable" when the meaning is Object Lock.

**ADR candidates:**

- **Name the platform bucket in the S3 account regional namespace** (only if Q1 is answered (c)).
  All three criteria hold. It is hard to reverse: after the first apply, a rename is a new bucket
  and a re-seed. It is surprising without context: a `-<region>-an` suffix that the state bucket
  does not share. It is a real trade-off: house consistency and a shorter name against guaranteed
  name ownership across teardown. If (b) is chosen instead, it is no longer surprising, because it
  mirrors the state bucket, so a consequence line in ADR-0012 is enough and no new ADR is needed.
- The Object Lock rejection is **not** a new ADR. It is a row in ADR-0009 (Q8, Q9).
