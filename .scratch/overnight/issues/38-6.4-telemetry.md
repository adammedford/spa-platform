### Standards (CODING_STANDARDS.md and the smell baseline)

- **S1, fixed (hard, "An assertion must be able to fail").** `N16_no_canary_appears_in_any_span` passed whether or not `AddPlatformTelemetry` drops `url.query`, because the ASP.NET Core and HttpClient instrumentation already redact query values by default. Checked: with the two `OTEL_DOTNET_EXPERIMENTAL_*_DISABLE_URL_QUERY_REDACTION` switches on and the enrichment removed, the server span carried `url.query=?access_token=PROBESPAN`; with the enrichment back it carried no `url.query`. The test now runs with both switches on, so it tests the gateway's own code.
- **S2, fixed (judgement).** In `Redaction.cs` the comment for the query-string regex sat above the template-hole regex. Moved, and rewritten for the new pattern.
- **S3, skipped (judgement).** `LogFloors` states YARP logs "Proxying to {destination}" with the query at Information without citing YARP. The claim is plausible and the floor is harmless either way; left for the author.
- No baseline smells worth raising: the floors are applied twice by design and the comment says why.

### Spec (ticket 38, plan row 6.4, contracts/telemetry.md, contracts/pipeline.md stage 2)

- **P1, fixed (implemented wrong: "Never logged ... query strings").** A query string with no non-space character before its `?` was not cut, so a value logged on its own leaked. Checked with the formatter: `LogInformation("query {Q}", "?code=PROBE1&state=PROBE2")` wrote `"msg":"query ?code=PROBE1&state=PROBE2"` and `"q":"?code=PROBE1..."`; `"Query: ?code=PROBE3"` was written unchanged. `HttpRequest.QueryString` renders with its leading `?`, so this is the natural way to log one. The regex no longer asks anything of the character before `?`; prose like "live? yes" still passes through. New test `A_query_string_logged_on_its_own_is_cut`.
- **P2, not a code finding: `rule` and `session_ref` missing from the request line.** The contract lists both; the task cannot add them without a shared type, and it raised `contracts/changes/6.4-request-telemetry-feature.md` (open), which is the route AGENTS.md prescribes. AGENTS.md says a task is done only when it leaves no change request open, so the integrator must decide that request before 6.4 counts as done. No box unticked: the boxes do not name those two fields.
- **P3, scope beyond the contract, accepted.** The `category` field and the extra floors (Duende, HttpLogging, YARP forwarder, HttpClient) are named in the Answer as implementer decisions; each only removes or labels output, so none weakens the never-logged list.
