## Answer

What landed:
- `S3ObjectStore`: `IObjectStore` over one bucket with `AWSSDK.S3`, already pinned in `Directory.Packages.props` and assigned to this project by `docs/dependencies.md`. A 304 maps to `NotModified` (the SDK throws on it; a mutation test proves the catch is load-bearing). `NoSuchKey` maps to null, while 403 and `NoSuchBucket` propagate. A write with no condition sends `If-None-Match: *`, and a conditional one sends `If-Match`. A 412, a 409 `ConditionalRequestConflict`, or `If-Match` on a missing key returns false. The caller's stream stays open. It passes the shared `ObjectStoreContract` against `FakeS3Server`, a fake S3 on loopback that the real SDK client talks HTTP to.
- `LiveRegistry`: the `IRegistry`. It starts at `LiveRegistry.NoSnapshot` (revision 0, no apps), replaces the snapshot with one reference write, then notifies. A subscriber that throws is logged and does not stop the others.
- `RegistrySource.RefreshAsync`: one poll. It runs a conditional GET, preloads secrets, validates (task 2.1), swaps, then notifies. A missing object, a store or read failure, a bad document, a revision that does not rise, or an unreadable secret while a snapshot is live all keep the last good snapshot. At a cold start, apps with unreadable secrets are left out and reported by appId and reference, and the rest go live. `RegistrySource.LeftOut` names them.
- `RegistryPoller`: a BackgroundService. It polls once at start, then every `Registry:PollSeconds` jittered, and catches every failure so it never stops the host.
- `PlatformPolicyConfiguration`: builds `PlatformPolicy` from `Policy:*` and `Issuers:*`, and fails closed.
- `AddPlatformRegistry`: now also registers `IAmazonS3`, `IObjectStore`, `PlatformPolicy`, `TimeProvider`, `LiveRegistry`/`IRegistry`, `RegistrySource` and the poller. Every registration is a TryAdd.

Acceptance, by test (`tests/Platform.Registry.Tests`):
- Concurrent readers: `RegistrySourceTests.Concurrent_readers_never_see_a_partial_snapshot` runs 4 readers through 40 swaps. `The_consistency_check_above_can_fail` proves the check can fail.
- Bad document changes nothing: `A_document_that_is_not_json_changes_nothing`, `A_document_that_breaks_a_rule_changes_nothing`, `A_document_whose_revision_does_not_rise_changes_nothing`, `A_store_failure_keeps_the_last_good_snapshot`, and `An_unreadable_secret_in_a_new_document_keeps_the_live_snapshot_whole`.
- One unreadable secret costs one app: `One_unreadable_secret_at_cold_start_costs_one_app_not_all`, which also checks that no secret value reaches a log line (N-16), and `An_app_left_out_at_cold_start_joins_once_its_secret_can_be_read`.
- Not ready until the first valid snapshot: `Before_any_document_is_read_nothing_is_live`, `A_missing_registry_object_leaves_the_gateway_not_ready`, `A_bad_first_document_leaves_the_gateway_not_ready`, and `RegistryPollerTests.With_no_registry_configuration_the_host_starts_and_nothing_goes_live`.
- Mutation checks: removing the 304 catch fails the contract suite. Breaking the cold-start/warm rule in either direction fails 1 and 3 tests respectively.

Seams (chosen by implementer):
- `IObjectStore`, with `S3ObjectStore(IAmazonS3, bucket)` behind it. Tested against `InMemoryObjectStore` and the SDK over HTTP.
- `IClientSecretSource`, tested against `FakeClientSecretSource`.
- `RegistrySource.RefreshAsync(ct)`, one poll, returning `RefreshOutcome`. The tests drive it directly.
- `IRegistry`/`LiveRegistry`, with the readiness signal `Current.Revision == 0` (`LiveRegistry.NoSnapshot`). Task 2.3's `/readyz` should answer 503 on revision 0 and 200 with `{"revision": N}` otherwise, using only `IRegistry`, so `Platform.Hosting` needs no reference to `Platform.Registry`.
- `RegistryPoller.NextDelay(interval, sample)`, a pure function, plus `TimeProvider` (`FakeTimeProvider` in tests).

Decided by implementer:
1. Jitter only shortens the wait: the delay is between 0.8 and 1.0 of `PollSeconds`. "Jittered by up to 20%" does not say which way, and shortening keeps "live within one poll interval" true.
2. A cold-start app left out because of its secret is retried on every poll while the object is unchanged. When its secret reads, it joins under the same revision and subscribers are notified. Without this it would stay out until the next registry revision, even though 2.5's source re-reads failed references on purpose.
3. If every app's secret is unreadable at a cold start, nothing goes live and the gateway stays not ready, so the ALB stays on tasks that work. A document with an empty `apps` array is still a valid snapshot and goes live, per contracts/README.md.
4. Once a cold-start snapshot is live, even a partial one, later documents follow the warm rule: one unreadable secret rejects the document whole (D3).
5. A document rejected by validation is remembered by ETag and not read again until it changes. A document refused only for its secrets is read again on the next poll.
6. `IObjectStore` is registered over `Registry:Bucket`. Phase 1 uses one bucket for the registry and the assets (`Assets:Bucket` description), so task 2.4 can reuse it or register a second store.
7. `PlatformPolicy` is registered as a singleton read from configuration. It fails closed: no `Policy:*` allows nothing, and an incomplete issuer is not an issuer.
8. With `Registry:*` incomplete, the poller logs one error and does not poll, and no AWS client is built. The SDK client constructors throw `AmazonClientException` when no region is set (verified on 4.0.101.6). A failure building the client while configured is logged on each poll.

Notes for other owners:
- `IRegistry` is now always registered, so ws4's `RegistryProxyConfigProvider(IRegistry?)` can drop its nullability. That file is theirs.
- `UsePlatformHealth` is untouched: the 503-to-200 change belongs to task 2.3.

Composed gateway, run by hand on port 5220 from the gate's Debug build with no platform config and no AWS environment (raw socket):
- `/healthz` 200, `/readyz` 503, every app path 404, and one "Registry:... not all configured" error.
- With `Registry__*` set and no region: `/healthz` 200, and "could not be polled (AmazonClientException: No RegionEndpoint...)" logged on every poll, about 0.8 to 1.0 s apart. The host keeps running.
