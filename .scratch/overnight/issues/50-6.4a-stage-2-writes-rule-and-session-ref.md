**What to build:** The rest of task 6.4. `IRequestTelemetryFeature` and `SessionRef` now exist in
`src/Platform.Abstractions`, and `SettableRequestTelemetryFeature` in `src/Platform.Testing`, from the
integrator's decision on change request 6.4 (14 October 2026). Stage 2 can now carry the two request

Contracts: `contracts/telemetry.md` — the log-field list, "How `rule` and `session_ref` reach the
request line", and "The instruments". Both sections were written for this.

What the contract now says, so none of it is a judgement call:

- Stage 2 sets the feature on the request **before** calling the rest of the pipeline, and reads it
  back after `next()`, in the same `finally` that already reads `IAppFeature`.
- Stage 2 counts `security.rejections` itself, from the feature's `Rule`, on its existing
  `Platform.Telemetry` meter through `IMeterFactory`, tagged `rule` and `app_id`. `app_id` is null
  for a request rejected before the app was resolved. No other project declares this instrument.
- `rule` is null on a request that was not rejected, and `session_ref` is null on a request with no
  session. Most requests have neither.
