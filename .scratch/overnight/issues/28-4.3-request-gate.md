- `src/Platform.Security/RequestGate.cs`: stage 6. Checks run in order: path form (`path.invalid`, 400 `invalid_request`), cookie names on every path (`gate.cookie-name`, 400 `invalid_request`), then the path's row: `/signout-oidc` and stray `/bff/*` (`path.reserved`, 404 `not_found`); callbacks GET only, assets GET/HEAD (`gate.method`, 405 with `Allow`); `/api` and `/bff/*` need `Sec-Fetch-Site: same-origin` (`none` too on `/bff/login`) (`gate.fetch-site`), an `Origin` equal to the app origin when sent and always on `/bff/logout` (`gate.origin`), then the method (`gate.method`), then `/bff/login` must be a document navigation (`gate.navigation`). **Rule ids this stage owns:** `path.invalid`, `path.reserved`, `gate.cookie-name`, `gate.fetch-site`, `gate.origin`, `gate.method`, `gate.navigation`. The rest belong to other stages: `host.unknown` to stage 4, `csrf.token` to stage 9 (4.4), `auth.*` to stages 7 and 8, `api.unknown` to the proxy (4.1). "Everything else needs a session" belongs to stage 8.

**Seams (chosen by implementer):** the public `UsePlatformRequestGate`, tested on a loopback Kestrel host. Stage 1 trusts loopback, so `X-Forwarded-Proto: https` gives the app origin `https://app1.spa-poc.test`. A one-line stand-in for stage 4 sets `SettableAppFeature.For(TestApps.Entry("app1"))`. The terminal sends `Access-Control-Allow-Origin: *` and a clearing `Set-Cookie` on purpose, so the assertions "no ACAO" and "no Set-Cookie" on a refusal fail if a request gets through. A raw socket carries the paths that `Uri` would normalise. What these tests catch: every rule id, status and code against the contract. What they miss: the live session surviving N-27 and the composed pipeline order (both for workstream 6), and the browser's own `__Host-` enforcement (N-25 is decided in a real browser).

**Decided by implementer:**
1. Any `Origin` that is sent must equal the app origin on every `/api` and `/bff` row, not only on `/api` and `/bff/logout`, because N-07 requires 403 for a foreign Origin on `/bff`. This is stricter than the table's "Nothing more" for `/bff/session` and `/bff/login`.
2. The app origin is `Request.Scheme` (after stage 1) + `://` + the pinned `App.Host`, compared without regard to case. `Origin: null` matches nothing.
3. Platform paths match without regard to case (`/BFF/session` is the session row), because endpoint routing and the OIDC handler match that way. Subpaths go to their row.
4. Any `/bff/*` path other than the three endpoints gets 404 `path.reserved`.
5. `path.invalid` reads the raw target and refuses: a target not in origin form (absolute form, asterisk form), `\`, `%2F`, `%5C`, `%2E` in any case, empty interior segments (`//`), and `.` or `..` segments, including `..;param`. An encoded dot that is legitimate gets refused as well. Kestrel already refuses `%00` before any middleware runs (verified).
6. Cookie rule: a name that starts `__Host-spa-` in a different letter case is refused. Two names that are equal ignoring case and start with the prefix count as "sent twice", because ASP.NET Core treats them as the same cookie. The rule reads every `Cookie` header field.
7. Check order: fetch-site, then origin, then method, so a cross-site caller learns nothing about which methods a path accepts.
8. If `IAppFeature` is missing, the gate throws (500) instead of passing the request on. The composed stage-4 stub short-circuits before stage 6, so this never fires in the composed gateway.

**Notes:** the gate logs `rule=` but increments no `security.rejections` counter. `MethodAllowlist` (4.6) and `UnknownApi` (4.1) work the same way, and the metric belongs to task 6.4's telemetry. N-27's framework half, clearing `RemoteSignOutPath` in the OIDC options, is identity's (3.2). The gate is the first line of defence, and workstream 6 proves the session survives in the composed suite. `ListLoggerProvider` is duplicated between `SecurityHost` and `GateHost`. A shared helper would belong in `Platform.Testing`, which is an integrator path.

### Standards (CODING_STANDARDS.md, AGENTS.md, smell baseline)

1. **Duplicated Code (fixed).** `ListLoggerProvider` was nested, byte for byte the same, in both `GateHost.cs` and `SecurityHost.cs`. The Answer gives a reason for the copy: a shared helper "would belong in `Platform.Testing`". That reason does not hold, because both hosts are in `tests/Platform.Security.Tests`, which is ws4's own path. The class is now in `tests/Platform.Security.Tests/ListLoggerProvider.cs` and both hosts use it.
2. **"Code that rests on vendor behaviour cites the vendor": I verified this by a run, and it needs no change.** The whole of `gate.cookie-name` rests on one claim: that ASP.NET Core matches request cookie names without regard to case. A throwaway probe in the test project, deleted afterwards, set `Cookie: theme=x; __host-spa-session=planted`, and `Request.Cookies["__Host-spa-session"]` returned `planted`. That confirms the claim. The contract states it too, so I added no URL, because I could not cite a vendor page I had not checked.
3. **"An assertion must be able to fail": met.** The terminal deliberately sends ACAO and a `Set-Cookie`, the `Reached` counter is checked, and a log line must exist for each rule id. Each refusal test would therefore fail if the request got through the gate.
4. **Comment density and citations: met.** The `PathString` and `RawTarget` docs, ADR-0007, T-C10, RFC 9110 and the fetch-metadata spec are all cited where the code relies on them.
5. Not a finding: `PlatformCookiePrefix` is a private constant, but `Platform.Abstractions` has no constant it should read instead. The prefix appears there only in a doc comment. Identity (3.x) will need the same prefix.

### Spec (ticket, plan row 4.3, contracts/request-gate.md, http-contract.md -> Errors, pipeline.md)

1. **All seven rule ids are implemented with the contract's status and code: met.** The ids are `path.invalid` and `gate.cookie-name` (400 `invalid_request`), `path.reserved` (404 `not_found`), `gate.fetch-site`, `gate.origin` and `gate.navigation` (403 `origin_rejected`), and `gate.method` (405 `method_not_allowed` with `Allow`). The structured log key `rule={Rule}` matches the one in `MethodAllowlist` (4.6).
