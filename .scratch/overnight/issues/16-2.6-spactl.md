**Seams (chosen by implementer)**
- `SpactlApp.RunAsync(args, SpactlEnvironment, ct)`: the command line itself, with the store factory, history, HTTP handler, writers and poll interval injected. Catches every command's behaviour and exit code; misses the real S3 and HTTP adapters.
- `IObjectStore` (Platform.Abstractions) with the Platform.Testing `InMemoryObjectStore` underneath a test decorator (`VersionedStore`) that records versions. Catches conditional-write behaviour; misses S3 itself.
- `IRegistryHistory` (spactl's own; not in Abstractions because only spactl reads history). The S3 adapter is unproven here by design (task 6.9).
- `/readyz` through an injected `HttpMessageHandler` stub that answers from the store's live revision.
- `ContractDocuments` in Platform.Registry, tested against the contract examples.

**Decided by implementer**
- `--config <platform-config.json>` is how spactl gets `PlatformPolicy`; it is schema-checked, then read by the gateway's `PlatformPolicyConfiguration`. Bucket/region come from `--outputs` (default `infra/envs/poc/outputs.json`) or `--bucket`/`--region`.
- Release prefix exists = `apps/{appId}/releases/{release}/index.html` exists (the one required object). Checked for every entry on every write (apply, activate, app add/remove, rollback) and by non-offline validate.
- `release publish` uploads `index.html` last; an object already present with identical bytes counts as published (so a stopped publish or a seed re-run can resume), different bytes refuse the release.
- `app add` on an appId already in the registry replaces the entry in place (the secret-rotation runbook); `--release` is optional then and keeps the live release, required for a new app. With no live registry, `app add` writes revision 1.
- `registry rollback` picks the version before the newest by position (never by ETag); `--to-revision N` reaches further back. The restored content is re-validated under today's policy and written conditional on the live ETag. A second rollback returns to where the first started.
- `wait` succeeds on a reported revision >= N; `--timeout` seconds, default 300; a 10-second per-request timeout.
- `registry validate --offline` checks the document and policy only; without it, validate also checks the live revision and release prefixes and writes nothing.
- `app remove` may leave an empty `apps` array (valid per contracts/README.md; task 1.7 refuses to deploy against it).

### Standards (CODING_STANDARDS.md plus the smell baseline)
- Comments say why and cite their source throughout: ADR-0009, s3-layout.md, contracts/README.md, the S3 ListObjectVersions ordering URL and the SDK v4 null-collection note. No violation.
- "An assertion must be able to fail": the round trip asserts that nothing under `apps/` was written twice. This assertion can fail. If spactl passed an ETag as `ifMatch` for release objects, the in-memory store would accept the overwrite and `Written` would hold the key twice. Not vacuous.
- "A guard reads the thing it guards": `Harness.RegistryKey` repeats `Commands.RegistryKey` as a literal, because `Commands` is internal. This is a judgement call, not a violation. The value comes from the contract, and the readiness stub and `LiveRegistry` would fail if spactl moved its key.
