## Answer

**Landed** on `task/3.8-access-token-source` (head `eb1008f`, forked from `overnight/2026-10-16` at `6d30d1f`).

- `src/Platform.Identity/AccessTokenSource.cs` — `IAccessTokenSource`. Under a per-session gate it reads the
  session record from the store (not the request's ticket), serves the access token if it has more than one
  minute left, otherwise refreshes through the library's `IOpenIdConnectUserTokenEndpoint` with both
  `ChallengeScheme` and `SignInScheme` named and no `resource` (T-B12), and writes the new tokens back into the
  same record with `ReplaceAsync` (same key, same expiry, no cookie issued: S-E2, T-B9). Only `invalid_grant`
  ends a session, and only after a re-read finds no newer refresh token (T-B8); the record is removed and the
  cookie cleared, and the result is `SessionEnded`. Any other failure (an outage, a non-`invalid_grant` error,
  the deadline) keeps the session and throws `IdentityProviderUnavailableException`. The request's cancellation
  token reaches nothing; the refresh has its own 10-second deadline (T-D9).
- `src/Platform.Identity/SessionGates.cs` — one refresh at a time per session (ADR-0017 decision 1), bounded to
  the calls in flight, and calls queued behind a failed refresh share its outcome rather than asking again (T-D6).
- `src/Platform.Identity/ProfileTokenEndpoints.cs` — the sentinel default scheme (`token-management:none`) and one
  library endpoint per `ClientCredentialStyle`, mapped by name, so each issuer's profile decides how the secret is
  presented on the refresh (ADR-0017 decision 2).
- `src/Platform.Identity/SessionKeyFeature.cs`, plus `AppBoundTicketStore` leaving the owned session's key on the
  request, so the source can re-read the same record.
- `src/Platform.Identity/IdentityProviderUnavailableException.cs` — the "fails the call" outcome.
- `PlatformIdentityExtensions`: `AddPlatformIdentity` registers the library, the gates, the endpoints and the
  source; `AddPlatformAccessTokenSource` (internal) binds `IAccessTokenSource`.
- Tests: `tests/Platform.Identity.Tests/AccessTokenSourceTests.cs` (15 cases) against the test identity provider
  through `IdentityGateway`, which gained a token probe path standing in for the proxy's token step and a way to
  make the browser go away mid-request; `RecordingSessionStore` gained an `AfterRead` hook for "another writer".

**Test ids:** F-03 (`A_due_token_is_refreshed_once...`), F-10 (`Fifty_parallel_calls...`), S-E2
(`A_refresh_rewrites_the_same_session...`), S-E3 and T-A1 (`Each_app_refreshes_with_its_own_client...`), T-A8
(`A_refused_refresh_ends_the_session...`), T-A9 (`A_provider_failure_other_than_a_refusal...`, 503 and 500),
T-B8 (`A_refusal_after_another_writer_refreshed...`), T-B16 (`A_browser_that_disconnects_mid_refresh...`).
Beyond the row: T-D6 (shared outage), T-D9 and T-D10 (deadline and its caveat, which ADR-0005 requires 3.8 to
prove), the profile credential style (standard = form body, cognito = Basic), and the one-minute margin.

**Mutations (each reverted):** no gate failed 2 of 120 (F-10, T-D6); no re-read failed 1 (T-B8); any failure
treated as a refusal failed 5 (T-A9 x2, T-D6, T-D9, T-D10); casting the credential style instead of mapping by
name failed 2 (both profile rows); linking the request's cancellation token into the refresh failed 1 (T-B16);
waiters not sharing an outage failed 1 (T-D6); a zero refresh margin failed 10.

**Seams (chosen by implementer):**
- `IAccessTokenSource.GetAsync` behind the framework's `UseAuthentication`, through `IdentityGateway`'s token probe
  path, against the real test identity provider (TestIdp) and its fault switches. Catches every behaviour the row
  names as the proxy would see it; misses the proxy's own mapping of outcomes to responses (task 4.2's tests).
- The provider's grant log (`TestIdentityProvider.RefreshGrants`) and the session store (`RecordingSessionStore`)
  as the observation points for what was sent and what was kept.
- `AddPlatformIdentity`'s registrations, resolved outside a request.

**Decided by implementer:**
1. The composed gateway does not get the `IAccessTokenSource` binding yet. Bound, it turned 18 ws6 composed tests
   red (`tests/Gateway.SecurityTests`, `tests/Gateway.IntegrationTests`): they call `/api` with no session, and the
   composed gateway cannot establish one while the shell gate and `/bff` are empty. `AddPlatformIdentity` registers
   everything else; the binding is `AddPlatformAccessTokenSource`, one line to move into `AddPlatformIdentity`.
2. "Fails the call" is `IdentityProviderUnavailableException` (a 500 through the proxy's step), because the frozen
   `AccessTokenResult` has no provider-unavailable outcome. Change request
   `contracts/changes/4.2-access-token-result-provider-unavailable.md` (open, names 3.8) already asks for one; no
   second request was raised.
3. Gateway-owned orchestration (ADR-0017's adopted reserve design) rather than the library's token manager: the
   library makes the refresh call only, so the sentinel's T-A7 cost cannot arise and no cookie is re-issued.
4. Provider deadline 10 seconds, the grace window task 1.8 gives Cognito (T-D10's caveat is proved, not removed).
5. A session with no refresh token whose access token is due is ended (`SessionEnded`), since it can never yield
   a token again.
6. The credential style falls back to the form body when the issuer's profile is not registered, matching the
   handler's own code exchange.
7. Calls that queued behind a refresh that ended the session get `SessionEnded`, not `Unauthenticated`.

## PR41 review correction — refresh errors and lost versioned writes

The earlier Spec review item 3 accepted a lost replacement as an in-process scope limit. A
controlled competing writer now demonstrates that the caller returned a token different from the
persisted winner. The source now rereads that winner after a lost replacement; a deterministic
regression first failed and then passed. Provider-controlled error text is also normalized before
it reaches platform logs or public exceptions. Vendor error logs are independently blocked by
telemetry's N-16 filters and formatter. These changes do not claim distributed refresh locking.
