## Comments

  by hand, and set it on `context.Features.Get<IRequestTelemetryFeature>()?.SessionRef`. The session

  and plan row 3.3's ticket-store adapter is the code that holds both the key and the request.

  instrument here.

  case comes up here: a 401 that reports the session's state is not a broken rule, and no new rule id
  may be invented without a gate.

## Answer

**What landed** (branch `task/3.9-bff-endpoints`, commit "Task 3.9: /bff/session, /bff/login, /bff/logout and the shell gate"):

- `src/Platform.Identity/Bff.cs` — `MapPlatformBff`: `GET /bff/session` (sub, name, email, `expiresAt` = `SessionRecord.ExpiresAt`, `csrfToken` from `ICsrfTokens.Issue`; `Cache-Control: no-store`; 401 `unauthenticated` problem, never a redirect), `GET /bff/login` (cookie sign-out discards the session, then challenge with `returnUrl` kept only when local, else `/`), `POST /bff/logout` (`SessionEnd`, `ICsrfTokens.Clear`, cookie sign-out, OIDC sign-out to the profile with `RedirectUri = "/"`). `ReturnUrl.LocalOrRoot` is the N-15 rule.
- `src/Platform.Identity/SessionEnd.cs` — logout's revocation: under `SessionGates`, re-reads the record (revokes the newest refresh token), revokes in the issuer profile's credential style, checks the provider's answer and logs it by outcome only (`revoked`, `http_503`, `no_revocation_endpoint`, `deadline_exceeded`, ...), always removes the session.
- `src/Platform.Identity/ShellGate.cs` — `UsePlatformShellGate`: unauthenticated GET/HEAD outside the reserved paths (`/bff`, `/api`, the callbacks, `/signout-oidc`, health) is challenged; task 3.5's events make that a redirect for a navigation and a 401 problem otherwise. Sets `auth.session` on the telemetry feature when a presented cookie resolves to no session (also on `/bff/session`'s 401).
- `src/Platform.Identity/CredentialStyles.cs` — the issuer-profile style lookup, now shared by the refresh (3.8) and the revocation.
- Tests: `tests/Platform.Identity.Tests/BffSessionTests.cs`, `BffLoginTests.cs`, `BffLogoutTests.cs`, `ShellGateTests.cs`, `TokenSearch.cs`, `CapturingLoggerProvider.cs`; `IdentityGateway` now runs routing, authentication, the shell gate and `MapPlatformBff` instead of stand-ins, and `LogoutTests` posts to the real `/bff/logout`.

**Test ids:** F-02 (`BffLoginTests.Each_app_redirects_...`), F-04 (`BffLogoutTests.Logout_revokes_...`), F-05 (`BffLogoutTests.A_signed_in_visit_leaves_two_cookies_...`), N-15 (`BffLoginTests.A_return_url_that_is_not_a_local_path_becomes_the_root`), N-19 /bff/session half (`BffSessionTests.Without_a_session_...`; the /api half is task 4.2's token step), N-23 (token search in the session, login and logout tests), S-E4 (`BffLogoutTests.Replaying_the_old_still_decryptable_cookie_after_logout_is_anonymous`).

**Seams (chosen by implementer):** the three `/bff` endpoints and the shell gate as HTTP, through the `IdentityGateway` harness (the services `AddPlatformIdentity` registers, the framework's authentication, the test identity provider, Platform.Testing's session store, `FakeCsrfTokens`, `StubIdpProfile`, `SettableRequestTelemetryFeature`); the provider's records (revocations, logouts, issued tokens) as the observable effect at the provider; the log lines as written to an `ILoggerProvider`.

**Decided by implementer:**
1. The shell gate is switched on by an internal `AddPlatformShellGate()` that the identity tests call, not by `AddPlatformIdentity`, following 3.8's precedent for `IAccessTokenSource`: with it on, 15 composed tests in `tests/Gateway.*` (ws6) went red because they request assets without signing in. `MapPlatformBff` is live in the composed gateway.
2. Revocation uses the token library's configuration service plus `Duende.IdentityModel`'s `RevokeTokenAsync` instead of the library's `RevokeRefreshTokenAsync`, because the latter returns nothing (4.2.0) and ADR-0017 decision 4 requires the provider's answer to be checked.
3. `auth.session` is written by the shell gate and `/bff/session` when a presented session cookie fails to authenticate (no cookie leaves it null).
4. `/bff/login` discards the session without revoking its refresh token (the contract says "discards"; only logout says "revoke").
5. The shell gate passes methods other than GET/HEAD through (they serve no asset and get their 405 later), and compares the reserved prefixes ignoring case, as the asset endpoint does.

### Standards

1. **Fixed: `SessionEnd.EndAsync` removed a record it had just decided was not this app's.** The ownership check returned from inside `try`, so the `finally` still called `ISessionStore.RemoveAsync` on a record whose `AppId` or `ClientId` did not match. That contradicts `AppBoundTicketStore.RemoveAsync` ("Another app's key is left alone"). It is unreachable today, because the key only reaches `SessionKeyFeature` after an owned retrieve, but the code said one thing and did another. Now the check runs before `try` and leaves a foreign record alone. The removal of an owned record is still in `finally`.
2. **Fixed: the log line said "removed session" before the removal ran.** It is written inside `try`, and the removal comes after it in `finally`. It now reads "is removing session".
3. **Addressed in the review: the merge body named no mutation** (CODING_STANDARDS.md, "A new invariant test names the mutation that made it fail"). The reviewer ran three mutations against `tests/Platform.Identity.Tests` (166 tests):
   - Dropping the second-character check in `ReturnUrl.IsLocal` failed 1 of 166 (N-15, `//evil.test`).
