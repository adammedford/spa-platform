## Answer

**What landed** (branch `task/2.4-asset-endpoint`, commits e7f34a8 and 710becd, forked from 2cb1a11):

- `src/Platform.Hosting/Assets.cs`: the stage-10 handler. It requires `IAppFeature` and throws without it. It returns 405 `method_not_allowed` with `Allow: GET, HEAD` for other methods, 404 `not_found` for reserved paths without reading anything, and 400 `invalid_request` for a path that fails validation. It builds the key as `apps/{AppId}/releases/{Release}/{relative}` and passes `If-None-Match` to `IObjectStore` unchanged. A match returns 304 with the ETag and Cache-Control. The content type comes from the extension via `FileExtensionContentTypeProvider`, with `application/octet-stream` for an unknown one, plus `nosniff`. Cache policy: `private, max-age=31536000, immutable` under `assets/`, otherwise `private, no-cache` with an ETag. The policy follows the key that is served. HEAD returns the headers and no body.
- `src/Platform.Hosting/AssetPath.cs`: two pure checks. `RawIsNormal` reads the raw target and refuses a backslash, an escaped `.`, `/`, `\` or NUL, a doubled slash, and a `.`/`..` segment (also with a `;` parameter). `Validate` reads the decoded path and refuses a backslash, `%`, a control character, an empty segment and `.`/`..`.
- `PlatformHostingExtensions.MapPlatformAssets`: `MapFallback("/{**path}", ...)` for every method, order int.MaxValue. `IObjectStore` is resolved per request, not when the endpoint is mapped. The S3 client throws with no region or bucket configured, and `RegistryPoller` deliberately defers building it so the gateway starts with no `Registry:*` (CI's G1a smoke test). `AssetStartupTests` fails if mapping the endpoint builds the store. I also started the built composed gateway with no configuration on port 5240: `/healthz` answered 200, and I stopped the process.
- `Problems.cs`: `invalid_request` and `method_not_allowed` codes added. `Platform.Hosting.csproj` gains `InternalsVisibleTo Platform.Hosting.Tests`.
- Tests: `tests/Platform.Hosting.Tests/AssetTests.cs` and `RecordingObjectStore.cs`. `HostingHost` takes an optional `IObjectStore`. With one, the terminal becomes `UseRouting` + `MapPlatformAssets` after the real stages 3 and 4.

**Test ids proved** in Platform.Hosting.Tests:
- F-01 (hosting half): two hosts return two different shells. Also a release switch and rollback by registry swap.
- F-06: an 18-row fallback matrix.
- N-13: 21 hostile request lines sent over a raw socket. Each gets 400 or 404, no leaked body, and every key read is inside app1's prefix and canonical. Each shape is also tested against both validators directly.
- Also covered: content type, cache policy, If-None-Match pass-through and 304, HEAD, 405, reserved paths and their controls.

**Mutation check:** I replaced validation with `Path[1..]`. 13 of the N-13 socket rows then fail. The rows that still pass are the ones Kestrel handles first: it collapses `%2e` dot segments and refuses `%00`.

**Seams (chosen by implementer):** the HTTP boundary of `MapPlatformAssets` behind the real `UsePlatformHealth` and `UsePlatformHostResolution`, over a recording `InMemoryObjectStore`, reached over a raw socket. Also `AssetPath`'s two pure functions, because Kestrel normalises some N-13 shapes before the endpoint sees them.

**Decided by implementer:**
1. "Accepts HTML" means no `Accept` header, or a range matching text/html with q>0 (`text/html`, `text/*`, `*/*`), per RFC 9110 12.5.1. An extensionless path with `Accept: application/json` gets the object at that path, or 404.
2. `/` always serves `index.html`. An extensionless path that accepts HTML goes straight to `index.html` without first looking for an object at that path.
3. "Extension" means a dot in the last segment after its first character and before its last. `.well-known` and `v1.` have none.
4. Reserved paths match ignoring case, as routing and the request gate do, so `/HEALTHZ/x` and `/BFF/x` get 404 at this stage. Stage 3 still answers only the exact `/healthz`.
5. The endpoint repeats the gate's path rules itself, as defence in depth: 400 `invalid_request` for a malformed path, 404 for reserved paths. It writes its own Warning log line with only the rule id (`path.invalid` / `path.reserved`), never the path.
6. A method other than GET or HEAD gets 405 with the contract's problem body, not routing's empty 405.
7. `nosniff` is set here as well as by stage 5.
8. `Range` and `If-Modified-Since` are ignored. `IObjectStore` takes only If-None-Match, and no `Last-Modified` is sent.
9. `Validate` refuses a literal `%` in the decoded path, so a release file whose name contains `%` (requested as `%25`) gets 400. Kestrel decodes every escape except `%2F` first, so a `%` that is left is either an encoded slash or a second round of encoding.
