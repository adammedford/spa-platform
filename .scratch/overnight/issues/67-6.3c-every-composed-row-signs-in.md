# 67: 6.3c — Every composed row signs in, or expects the login it is refused for
**Task:** 6.3c
**Owner:** ws6-verification
**Blocked by:** None
**Status:** resolved

**What to build:** Q24, accepted 2026-10-16. The shipping gateway is about to require a session:
ticket 26 (task 3.9) moves the shell gate and the `IAccessTokenSource` binding into
`AddPlatformIdentity`. Turning them on before was 15 to 18 red composed tests, every one a row that
requests an asset or `/api` without signing in. Make each composed row either sign in first or assert
the refusal a sessionless request now gets: a navigation is redirected to the provider, a fetch gets
401 `unauthenticated` under `auth.session` where a cookie was presented, `/api` gets 401 from the
token step.

Scope: `tests/Gateway.SecurityTests` (6.3a's shared sessionless fixtures, the largest group),
`tests/Gateway.IntegrationTests` (anything still on `SessionRequired = false`), and `tests/e2e`.
`GatewayHarnessOptions.SessionRequired` defaults to **true** from this ticket, so the suites run
the composition that will ship; a row that is about the sessionless path says so by asserting the
refusal, never by turning the gate off. Keep the reflection in `GatewayHarness.RequireSession` for
now: it is what turns the gate on until ticket 26 lands, and ticket 36 removes it after.

**Done when:** every test project is green with `SessionRequired` defaulting to true; no composed
test sets it to false; a mutation that turns the shell gate off fails at least one row in each of
the three projects (watched failing).

**Decided by implementer** (gap decisions, each reversible and inside workstream 6's paths):

1. **N-09's distrusting cell gets a session carried in from a trusting cell.** The session record is
   copied into the cell's own store, and a cookie naming the new key is encrypted with that cell's
   own format. The cell cannot complete a login of its own: it ignores the load balancer's
   `X-Forwarded-Proto`, builds an `http` callback, and the provider refuses it
