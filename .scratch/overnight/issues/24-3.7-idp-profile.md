## Answer

Landed on `task/3.7-idp-profile` (worktree `/Users/adammedford/.worktrees/overnight-2026-10-16/ws3-identity`), commit subject "Task 3.7: standard and cognito IdP profiles, with the sign-out redirect owned by the issuer's profile".

- `src/Platform.Identity/IdpProfiles.cs`: `StandardIdpProfile` (`standard`, `PostBody`) keeps the handler's RP-initiated logout from discovery; `CognitoIdpProfile` (`cognito`, `AuthorizationHeader`) redirects to `{BrowserOrigin}/logout?client_id=…&logout_uri=https://{host}/` and marks the response handled, so no state and no `end_session_endpoint` are needed.
- `src/Platform.Identity/OidcOptionsSetup.cs`: when the issuer's profile is registered, `OnRedirectToIdentityProviderForSignOut` calls `profile.RedirectToSignOutAsync(context, app, issuer)`.
- `src/Platform.Identity/PlatformIdentityExtensions.cs`: `AddPlatformIdentity` registers both profiles with `TryAddEnumerable`. A host's own profile registered first still wins, which the `StubIdpProfile` tests rely on.
- Tests: `tests/Platform.Identity.Tests/LogoutTests.cs` (R-C6 standard end to end; the Cognito style end to end against the test provider in `EndSessionStyle.Cognito`; R-C7; the profile is consulted for the right app and issuer) and `IdpProfileTests.cs` (one profile per name in the schema's `Profile` enum, read from `contracts/platform-config.schema.json`; the credential styles; the Cognito redirect goes to the browser origin, not the authority; standard leaves the request as the handler built it). `IdentityGateway` gained `LogoutPath`, which stands in for `/bff/logout`, plus `issuerProfile` and `stubProfile` parameters, and it now registers each client's `/signout-callback-oidc` and `/` as post-logout URIs.
- Mutations: browser origin to authority failed 1 of 105; standard dropping `id_token_hint` failed 2; removing the sign-out wiring failed 2; not registering cognito failed 4; cognito landing on the callback failed 2.

Seams (chosen by implementer): the composed identity services through `IdentityGateway`, meaning logout and the signed-out callback against the test provider; the `IIdpProfile` public interface; and `AddPlatformIdentity`'s registrations.

Decided by implementer:
- The sign-out event is wired in `OidcOptionsSetup`, next to the profile's `Configure`, not in `AuthenticationEvents.Apply`, because the setup has the app and the issuer.
- An issuer whose profile is not registered keeps the handler's own RP-initiated logout.
- Cognito's `logout_uri` is the root of the request's own scheme and host, the same base the handler uses for the login's redirect URI.
- Both profiles' `Configure` are empty: nothing in 3.2's options needs a provider refinement yet.
- The code exchange still sends the secret in the form body, which is the OIDC handler's only style. Cognito accepts that at the exchange (C-2.19). Moving the exchange to a Basic header would mean redeeming the code outside the handler with the token library, which `Platform.Identity` does not reference until 3.8. ADR-0005 says all three calls use the profile's style, so 3.8 or the integrator should decide whether the exchange must follow.

Gate: `.scratch/overnight/log/3.7-implement.txt`, GATE: GREEN, total 1348, failed 0, succeeded 1348.

Outstanding: task 6.9 repeats this against real Cognito. That includes the open question from ADR-0011 and ADR-0017 about whether the standard profile's RP-initiated logout works against Cognito, which this task did not exercise.
