## Answer

Landed on branch `task/4.6-forwarded-limits`, commits 3c87fac and 1112fa1, forked from overnight/2026-10-13 at f856503.

- `src/Platform.Security/PlatformForwardedHeaders.cs`: `ForwardedHeadersOptions` from `ForwardedHeaders:TrustedNetworks` into `KnownIPNetworks`. Only `XForwardedFor | XForwardedProto` are applied, with `ForwardLimit = 1`, and `X-Forwarded-Host` is never read. The framework's loopback defaults (`KnownProxies` ::1, 127.0.0.0/8) are cleared. A CIDR that does not parse stops the gateway at start-up.
- `src/Platform.Security/MethodAllowlist.cs`: the stage-1 method allowlist. Allowed: GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS. Any other method (TRACE, CONNECT, TRACK, PROPFIND...) gets 405 `method_not_allowed` as problem+json, with `Allow` set and a log line carrying `rule=gate.method` but not the method itself.
- `src/Platform.Security/PlatformSecurityLimits.cs`: pins Kestrel's limits explicitly (32 KB of headers, 100 headers, an 8 KB request line, a 30,000,000-byte body). These are Kestrel's defaults. Kestrel refuses oversized headers itself with 431 and no body.
- `src/Platform.Security/Problems.cs`: Security's problem-details writer, which writes the same two fields as `Platform.Proxy.Problems` (A-03 rules out sharing it).
- Tests: `tests/Platform.Security.Tests/ForwardedHeadersTests.cs` (N-09, both directions), `RequestLimitsTests.cs` (N-20). The socket tests bracket the configured limits, and a separate test proves `AddPlatformSecurity` applies them, because the limits equal Kestrel's defaults. `SecurityHost.cs` is a loopback host with a raw-socket sender.

Seams (chosen by implementer): one seam, the HTTP behaviour of a loopback host composed of `AddPlatformSecurity` and `UsePlatformForwardedHeaders` with an echo terminal. It is exercised with HttpClient, plus a raw socket for CONNECT and oversized headers. The trusted networks come from `ForwardedHeaders:TrustedNetworks` in configuration.

Decided by implementer:
- The method allowlist is global and runs in stage 1, the only middleware entry point task 4.6 owns. Per-path methods, including N-20's "unsafe method on an asset path" (`Everything else: GET, HEAD`), are the request gate's `gate.method` rule, stage 6, task 4.3. N-20 is proved here for TRACE, CONNECT and oversized headers. The asset-path case is 4.3's to prove.
- With no `ForwardedHeaders:TrustedNetworks`, no forwarded header is processed: `ForwardedHeaders = None`, and the gateway still starts. The middleware treats empty KnownProxies and KnownIPNetworks as "trust every sender", and a test found it.
- The request limits are Kestrel's own defaults, set explicitly.
- No gateway-wide fallback writes a problem body into bodiless error responses from other stages (a routing 404/405, the stage-4 stub). Each stage writes its own problem details.

### Standards (CODING_STANDARDS.md, AGENTS.md, smell baseline)

1. **Fixed.** `PlatformSecurityLimits` doc comment said a framework upgrade that moved a Kestrel default "would show up as a test failure here". Nothing compares the constants with Kestrel's defaults, so that could not fail. Checked by reading every test that touches the limits: the socket tests use the constants, and `AddPlatformSecurity_applies_the_limits_to_kestrel` seeds 1 and asserts the configured values. The comment now says what is actually true: the limits are set explicitly so a moved default does not move them, and the test proves they are applied.
2. **Fixed.** "A guard reads the thing it guards": `AddPlatformSecurity_applies_the_limits_to_kestrel` repeated the literals (32 * 1024, 100, 8 * 1024, 30_000_000). It now asserts against the `PlatformSecurityLimits` constants. It can still fail, because every limit is seeded to 1 first.
3. **Fixed.** "Code that rests on vendor behaviour cites the vendor": the claim that `ForwardedHeadersMiddleware` trusts every sender when both `KnownProxies` and `KnownIPNetworks` are empty was backed only by a test. It now also cites the middleware's source.
4. **Skipped (possible Duplicated Code):** `Problems.cs` copies `Platform.Proxy.Problems`, and `SecurityHost` repeats `Platform.Proxy.Tests.Loopback`. A-03 forbids the shared reference, and a shared test helper belongs in `Platform.Testing` (an integrator path). Both are documented in the code.
5. **Skipped (judgement):** the refusal logs at Warning, so a client controls how much is logged. It carries no client value and matches the other stages' refusals. Telemetry (6.x) owns how rejections are counted.
6. **Skipped (minor test hygiene):** if `StartAsync` throws in the bad-CIDR test, the `WebApplication` is never disposed. The pipeline is built before Kestrel binds, so no port is leaked. The echo terminal in `SecurityHost` writes with the test's token, not `RequestAborted`, which does no harm.
