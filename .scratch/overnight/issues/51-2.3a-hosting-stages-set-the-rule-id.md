# 51: 2.3a — Host resolution and the asset endpoint set their rule id on the telemetry feature
**Task:** 2.3a
**Owner:** ws2-hosting
**Blocked by:** None
**Status:** resolved

**What to build:** Two landed stages in `src/Platform.Hosting` reject requests, and neither can say so
on the request log line. `IRequestTelemetryFeature` now exists in `src/Platform.Abstractions` for
exactly that (integrator's decision on change request 6.4, 14 October 2026).

| Rule ids | Where | From task | Today |
| --- | --- | --- | --- |
| `host.unknown` | `src/Platform.Hosting/HostResolution.cs` | 2.3 | Writes a bare 404 and logs nothing. The id appears nowhere in `src/` |
| `path.invalid`, `path.reserved` | `src/Platform.Hosting/Assets.cs` | 2.4 | Writes its own Warning line with a `{Rule}` property |

Write the id null-conditionally, because a stage's own test project runs without stage 2:

```csharp
context.Features.Get<IRequestTelemetryFeature>()?.Rule = RuleIds.HostUnknown;
```

Contracts: `contracts/request-gate.md` for the ids, `contracts/telemetry.md` -> "How `rule` and
`session_ref` reach the request line".

Two decisions already made, so they are not open here:

- **`HostResolution` sets the field and adds no Warning line of its own.** Unknown hosts are the
  cheapest traffic for anyone to send, so a line each would let a stranger flood the log. The request
  line and `security.rejections` record the rejection once.
- **`Assets` keeps its existing Warning line.** It carries detail the request line does not, and
  `AssetTests` asserts on it. Removing it is this owner's choice, not a contract matter.

## Acceptance
- [ ] Each of the three rule ids above is set on the feature by the stage that rejects under it
- [ ] Every write is null-conditional, and each stage's own tests still pass with no feature installed
- [ ] A test per id asserts the stage set it, using `SettableRequestTelemetryFeature` from
      `Platform.Testing`. The assertion must be able to fail: a stage that sets the wrong id, or none,
      fails it
- [ ] `HostResolution` adds no log line for an unknown host
- [ ] The ids are not spelled as bare literals in more than one place if the project already has a
      constant for them; if it does not, one constant per id in this project is enough. Do not reach
      into `Platform.Security` for one — A-03 forbids it
- [ ] `dotnet test --project tests/Platform.Hosting.Tests` is green
- [ ] Writes only `src/Platform.Hosting` and `tests/Platform.Hosting.Tests`
