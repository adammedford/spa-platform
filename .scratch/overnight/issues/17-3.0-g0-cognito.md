## Proposed glossary / ADR

**Glossary terms (proposed; GLOSSARY.md not edited):**
- **G0 item**: one of the five numbered things Gate G0 must prove (`01-plan.md`, "What Gate G0 must still prove"). Not to be confused with an **item 2 question**, one of the five Cognito questions listed under item 2.
- **Way out**: the fallback the plan names for a gate item that fails. Taking it does not fail the gate. Avoid "plan B".
- **Refresh rotation**: every refresh grant returns a new refresh token and retires the one sent. The token sent is the **rotated-out token**, and the one returned is its **successor**.
- **Grace window**: how long the provider still honours a rotated-out token. Cognito's is set to 10 seconds by task 1.8. It is **insufficient** if a replay inside the window is refused, or a replay after it invalidates the successor.
- **Replay**: a refresh grant that sends a rotated-out token, usually from a request that read the session before another request's refresh finished.
- **Managed login**: the provider-hosted login page that a branding style styles. The browser visits it at the issuer's browser origin.
- **OAuth client**: the provider-side client one app owns: client id, secret, scopes and callback URLs. Avoid "app client", Cognito's console term, outside Cognito-specific text.
- **Issuer name** and **authority**: an entry's `oauth.issuer` is a name (`cognito-poc`) that platform configuration maps to an authority, the provider's issuer URL (`Issuers:{name}:Authority`). Don't say "issuer" alone where the difference matters.
- **Expectation / finding**: in a G0 harness, an expectation either holds or fails the run (`BAD`). A finding is a probe that confirmed something the plan must allow for, and it does not fail the run.
- **Evidence ids** (amend): add `C-`, the Cognito run (G0 items 2 and 3), listed in `spikes/g0/README.md`.

**ADR candidates:** none unconditional. Task 3.0 gathers evidence, and I-6's planned decision record (ADR-0014) records what the evidence decides. Two outcomes would each meet all three criteria (hard to reverse, surprising, a real trade-off) and deserve their own ADR or status change:
- If Q11 finds the grace window insufficient: ADR-0005 is superseded, and the reserve design (gateway-owned locking) is adopted over the library's token manager.
- If Q15 finds that resource binding does not set `aud`: the "Resource binding" decision is revised, so APIs authorise Cognito tokens by `client_id` and scope, and audience binding waits for Phase 2.
