**Tests:**
- F-06 headers: baseline + provider origin for an app with no additions; two apps on one gateway get their own policies (data: in img-src, connect-src and form-action additions); additions to a `'none'` directive.
- N-24: shell, asset, `/bff/session`, API error (a real 403 written by stage 6 after stage 5), and a proxied API success. Each gets one value of every header, `frame-ancestors 'none'` among them, and no `Access-Control-*`, even though the terminal sends conflicting copies of all of them.
- I checked that the strip test can fail: with the removal disabled, 4 of the N-24 cases fail.

**Seams (chosen by implementer):** the HTTP seam of the public entry points only: `AddPlatformSecurity` + `UsePlatformSecurityHeaders`, in a cut-down host with stage 1, a stage-4 stand-in that pins `SettableAppFeature` by `Host`, the real stage 6 and a terminal that stands for stage 10. Platform.Security has no `InternalsVisibleTo`, so the CSP builder is tested only through response headers.

**Decided by implementer:**
1. The provider origin is read from `IConfiguration` at `Issuers:{app.OAuth.Issuer}:BrowserOrigin` as a raw string. `PlatformPolicy` is not registered in DI, and a `Uri` would add a trailing slash.
2. An addition to a directive whose baseline is `'none'` (frame-ancestors, object-src) replaces `'none'`. CSP3 says `'none'` has no effect beside other sources, so browsers enforce the same policy either way and the header now says what they do.
3. A source containing `;`, `,`, whitespace or a control character is dropped, with a warning that names the app and directive (not the source). The schema's `^\S+$` lets `;` and `,` through. Spliced in as written, a `default-src` source like `x;script-src` followed by `'unsafe-inline'` would put a `script-src 'unsafe-inline'` ahead of the baseline's, and the browser keeps the first.
4. A missing issuer origin, or a missing `IAppFeature`, throws and the request gets a 500. This fails closed, like stages 6 and 9.
5. Csp keys outside the ten are ignored, because the builder walks the baseline and never the entry.

**Gate:** GREEN, `.scratch/overnight/log/4.5-implement.txt`: "total: 678, failed: 0, succeeded: 678, skipped: 0".

**For Adam (not blocking, no change request filed):** `registry.schema.json`'s `cspSource` pattern could also refuse `;` and `,`, so spactl rejects such an entry at publish time instead of the gateway dropping it at runtime. That is an integrator edit.

### Spec (ticket, plan row 4.5, http-contract.md Response headers, registry.schema.json csp)

- **F-06 per-app CSP:** met. **N-24 on shell, asset, `/bff`, API error:** met, plus a proxied success. **Upstream copies overwritten, `Access-Control-*` stripped:** met. All acceptance boxes stay ticked.
- **CONFIRMED and fixed (correctness):** when every addition to a `'none'` directive (`frame-ancestors`, `object-src`) failed `CanSplice`, the builder had already cleared `'none'`. The directive then went out empty. Proven by a new test, which failed with `Actual: ... frame-ancestors ; base-uri ...`. CSP3 treats an empty list like `'none'`, so browsers were not loosened, but the header no longer showed the baseline. Now `'none'` is cleared only when at least one source survives. Test: `A_none_directive_whose_every_addition_is_dropped_keeps_none`.
- **Accepted deviations (implementer's decisions 2 to 5):**
  - Replacing `'none'` follows CSP3 semantics.
  - Dropping `;` and `,` sources is stricter than the schema and never looser.
  - Failing closed with a 500 when the issuer origin or `IAppFeature` is missing matches stages 6 and 9.
  - Ignoring keys outside the ten is moot because of the schema.
- **Skipped, out of scope:**
  - The policy is cached per `AppDefinition`, so a hot reload of `Issuers:*:BrowserOrigin` alone is not picked up until the registry swaps. Issuer settings are startup configuration.
  - The 500 thrown by `Build` carries none of the fixed headers, because it fires before `OnStarting` is registered. That response is empty and comes from a misconfigured gateway.
  - An upstream `Content-Security-Policy-Report-Only` is not stripped. The contract does not ask for it, and it cannot loosen enforcement.

The commit is a1d5de9, "Review: keep 'none' when every addition to a 'none' directive is dropped". The schema hardening suggested for Adam in the Answer section still stands. It is an integrator edit and does not block this task.
