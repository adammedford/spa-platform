## Answer

**Landed** on `task/3.5-events` (commit "Task 3.5: authentication events - 401 for a fetch, sub/name/email tickets, one failure page"), forked from `overnight/2026-10-16` at `a208c85`.

- `src/Platform.Identity/AuthenticationEvents.cs`: the OpenID Connect events, applied by `OidcOptionsSetup` *after* the profile's `Configure`, so they wrap what the profile set.
  - `OnRedirectToIdentityProvider`: if the request is not a navigation (`Sec-Fetch-Mode: navigate`, sent once), it answers 401 `application/problem+json` `{"status":401,"code":"unauthenticated"}`, removes the nonce and correlation `Set-Cookie`s the handler had already written, and does not call the profile's handler. A navigation goes on to the profile's handler, then to the redirect.
  - `OnTicketReceived`: the profile's handler runs first. Then the principal is cut down to one identity holding only `sub`, `name` and `email`, with the same authentication type and name/role claim types. Tokens stay in the ticket properties.
  - `OnRemoteFailure`: every refused callback, the provider's `access_denied` included, gets one constant HTML page (400, `text/html; charset=utf-8`, `Cache-Control: no-store`). It sets `Rule = RuleIds.AuthCallback` on `IRequestTelemetryFeature`, null-conditionally.
- `src/Platform.Identity/Problems.cs`: Identity's own problem+json writer. A-03 rules out sharing Security's or Proxy's writer.
- Tests: `tests/Platform.Identity.Tests/AuthenticationEventsTests.cs` has 5 new tests. Also new: `RemoteFailureRecorder.cs`, which records the handler's reason because the page no longer shows it. Changed: `IdentityGateway` (request headers, the `Navigation`/`Fetch` metadata presets, and `Rule`/`ContentType`/`Body` on `Answer`); the challenge callers in `ChallengeTests`/`SessionIsolationTests` now send navigation metadata; `CallbackRejectionTests` reads the reason from the recorder and asserts the page.

**Seams (chosen by implementer):** `AddPlatformIdentity`'s services behind the framework's `UseAuthentication`, with the real `OpenIdConnectHandler`, `fixtures/TestIdp` and the Platform.Testing doubles (the existing `IdentityGateway` harness). Behaviour is observed at the HTTP answer, at the stored `SessionRecord` (through `ISessionStore`) and at `IRequestTelemetryFeature`.

**Mutations:** treating every request as a navigation failed 2 of 85. Appending `error_description` to the page failed 1 of 85.

**Gate:** GREEN. Last summary line: `total: 1328, failed: 0, succeeded: 1328, skipped: 0`. Log: `.scratch/overnight/log/3.5-implement.txt`.

**Decided by implementer:**
1. A request counts as a navigation only when it carries exactly one `Sec-Fetch-Mode: navigate`. A request with no fetch metadata gets 401, not a redirect. This fails closed and matches how the request gate reads a missing header. `Sec-Fetch-Dest` is not consulted.
2. The failure page is HTML with status 400, not problem+json. `contracts/http-contract.md` → Errors has no row for a refused callback, and the callback is a navigation. The status and format are easy to reverse; an integrator may want to add an Errors row.
3. The fetch 401 sets no rule id, following the integrator's task 4.2 precedent. The failure page sets `auth.callback` now, per the integrator note on this ticket. Ticket 56 (3.5a) still owes `auth.session` and its own checks.
4. The page links to `/` to start a fresh login. It has no style or script, so the baseline CSP needs nothing added.
5. `OnRemoteFailure` is not chained to a profile's handler: the page belongs to the gateway alone.

Outstanding: none for row 3.5.
