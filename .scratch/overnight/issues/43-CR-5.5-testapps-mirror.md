## Proposed glossary / ADR

### Glossary (proposed, not applied)

- **Registry entry**: one app's object in the registry, which is its app definition plus `clientId`, `clientSecretRef` and `release`. It is what the gateway validates and serves from. Avoid "app definition" for it, because that term means the smaller, pre-onboarding shape. *(The term is already used inside the App definition entry but is not defined on its own.)*
- **Test double**: an in-process stand-in for one platform interface or record, used by component tests so a workstream builds without another's code. A double answers to the interface it stands in for, not to any fixture. Not "mock" and not "fixture".
- **Fixture**: a file or program that stands in for something real outside the gateway, such as an app's definition, the identity provider, an upstream API or a Cognito pool. The composed and deployed tiers run against fixtures. Not "test double".
- Under **Test double**, add a word to avoid: **"mirror"**. A double never mirrors a fixture. If a test needs a fixture's values, it reads the fixture.

### ADR candidates

None. A comment edit and a row in a dependencies table are trivially reversible (criterion 1 fails). Keeping a double's defaults minimal is not surprising (criterion 2 fails). Q11's choice not to rename `AppDefinition` is a real trade-off, but it is reversible at the next gate and unsurprising given the freeze, so it does not qualify either.
