# `infra/envs/poc/idp` — the identity root

Task 1.1. One user pool per cell, and what hangs off it:

| Resource | Where it comes from |
| --- | --- |
| User pool on the **Essentials** plan, admin-created users only, no MFA | `infra/modules/idp-cognito` |
| Prefix domain on **managed login** (`managed_login_version = 2`) | `domain_prefix`, default `spa-platform-<cell>-<account id>` |
| Resource servers and their scopes | `fixtures/cognito/pool.json` -> `resourceServers` |
| Test users, confirmed, with a permanent generated password | `fixtures/cognito/pool.json` -> `users` |
| One `SecureString` parameter per test user | `/spa-platform/<cell>/test-users/<username>` |

**No app clients.** Those belong to the apps root (task 1.8), so onboarding an app never plans a
change here (`docs/plan/05-infrastructure-and-cost.md` -> Terraform boundaries).

## Tags

`Platform = spa-platform`, `Cell = <cell>`, `ManagedBy = terraform`, through the provider's
`default_tags` (`contracts/resource-tags.md`). The pool and the parameters are tagged. The domain,
the resource servers and the users accept no tags, and all three are children of the pool, so
destroying the pool removes them and the teardown query stays a proof.

## Passwords

Generated by `random_password`, written to Parameter Store and set on the user. They are in state,
because the Cognito user resource stores its password, and the state bucket is private, encrypted
and TLS only. They are never in an output: `test_users` names each parameter, never the value.

Read one when a test needs it, and never into a file:

```bash
aws ssm get-parameter --with-decryption --name /spa-platform/poc/test-users/alice \
  --query Parameter.Value --output text
```

## Applying it

The backend block is partial, because the bucket name carries the account id:

```bash
cd infra/envs/poc/idp
terraform init -backend-config="bucket=$(terraform -chdir=../../../bootstrap output -raw state_bucket)"
terraform plan -out=idp.tfplan
terraform apply idp.tfplan
```

## Done when: the issuer's discovery document loads

```bash
curl -fsS "$(terraform output -raw issuer)/.well-known/openid-configuration" | jq '{issuer, authorization_endpoint, token_endpoint}'
```

`issuer` in the document must equal `terraform output -raw issuer`, and `authorization_endpoint`
must be on `https://$(terraform output -raw cognito_domain)`.

This is also the first root on the S3 backend, so it is where task 1.0's lock check runs; see
`infra/bootstrap/README.md` -> Verifying the lock.

## Outputs

| Output | Feeds |
| --- | --- |
| `issuer` | `issuer` in `contracts/infra-outputs.schema.json`; `Issuers:{name}:Authority` |
| `cognito_domain` | `cognitoDomain`; `Issuers:{name}:BrowserOrigin` is `https://` plus it |
| `test_users` | `testUsers`, already in the contract's shape |
| `region`, `cell` | `region`, `cell` |
| `user_pool_id`, `user_pool_arn`, `resource_servers` | The apps root (task 1.8) |

## Tests

Plans against a mock AWS provider, so they need no credentials:

```bash
terraform -chdir=infra/modules/idp-cognito init -backend=false && terraform -chdir=infra/modules/idp-cognito test
terraform -chdir=infra/envs/poc/idp init -backend=false && terraform -chdir=infra/envs/poc/idp test
```

The root's tests read `fixtures/cognito/pool.json` and `contracts/resource-tags.md` rather than
repeating them. CI's Terraform job runs `fmt` and `validate` only, not `terraform test`.
